## Как готовиться
1. Разберите один реальный сложный баг из своего опыта по схеме: симптомы → гипотезы → инструменты → причина → исправление → предотвращение.
2. Потренируйте `git rebase -i`, `git bisect`, `git reflog` на учебном репозитории — уверенность в git видна сразу.
3. Подготовьте ответы на HR-вопросы из [банка вопросов](../quizzes/quiz.html?id=17-debugging-git-team/interview-bank): о себе, последний проект, несогласие на ревью, срыв сроков.

## Самопроверка раздела (топ-10 вопросов)
1. Опишите свою методику поиска бага, который воспроизводится только у части пользователей.
2. Какие возможности DevTools вы используете, кроме `console.log`?
3. Как найти утечку памяти в SPA?
4. Merge, rebase, squash — что когда?
5. Как разрешить конфликт и как уменьшить их количество?
6. Как восстановить удалённую ветку или «потерянный» коммит?
7. Что вы проверяете в pull request и как пишете комментарии?
8. Как реагируете на ревью, с которым не согласны?
9. Как оцениваете задачи и что делаете, если не успеваете?
10. Как решаете спор с дизайнером или бэкендером?
