## Вопросы

<details><summary>Что такое Node.js и зачем он фронтенд-разработчику?</summary>

Среда выполнения JS вне браузера (V8 + libuv). Для фронтенда — платформа инструментов (сборщики, линтеры, тесты, dev-сервер), SSR-фреймворков (Next.js, Nuxt) и BFF.
</details>

<details><summary>Что такое npm-скрипты и `npx`?</summary>

`scripts` в `package.json` — команды проекта (`npm run build`), бинарники из `node_modules/.bin` доступны без пути. `npx`/`pnpm dlx` — запуск пакета без глобальной установки.
</details>

<details><summary>Чем `dependencies` отличаются от `devDependencies`?</summary>

`dependencies` нужны в рантайме (для библиотеки — устанавливаются у потребителя), `devDependencies` — только для разработки и сборки. Для приложения, которое собирается в бандл, разница в основном организационная.
</details>

<details><summary>Что означают `^` и `~` в версиях?</summary>

`^1.2.3` — любые версии до `2.0.0` (minor и patch), `~1.2.3` — только patch до `1.3.0`. Точная фиксация — без префикса.
</details>

<details><summary>Что делает сборщик?</summary>

Собирает модули в оптимизированные файлы для браузера: резолвит импорты, транспилирует TS/JSX, обрабатывает CSS и ассеты, удаляет неиспользуемый код, минифицирует, делит на чанки, добавляет хэши. Подробно — [Сборщики](01-bundlers.md).
</details>

<details><summary>Что такое транспиляция и полифил? Чем отличаются?</summary>

Транспиляция переписывает синтаксис (`?.`, классы, JSX) в поддерживаемый целевой средой. Полифил добавляет отсутствующие API во время выполнения (`Array.prototype.at`, `Promise.withResolvers`). Синтаксис полифилом не добавить, API — транспиляцией.
</details>

<details><summary>Что такое sourcemap?</summary>

Файл соответствия собранного кода исходникам — для отладки и читаемых стектрейсов.
</details>

<details><summary>Чем `git merge` отличается от `git rebase`?</summary>

Merge объединяет ветки merge-коммитом, сохраняя историю. Rebase переносит коммиты поверх другой ветки — линейная история, но новые хэши; не применять к общим веткам.
</details>

<details><summary>Как отменить последний коммит?</summary>

Ещё не отправлен: `git reset --soft HEAD~1` (изменения остаются в индексе) или `--mixed`. Уже отправлен в общую ветку: `git revert <hash>` — новый коммит, отменяющий изменения, без переписывания истории.
</details>

<details><summary>Что такое `git stash`?</summary>

Временное сохранение незакоммиченных изменений, чтобы переключиться на другую задачу: `git stash push -m "wip"`, затем `git stash pop`.
</details>

<details><summary>Чем unit-тест отличается от e2e?</summary>

Unit проверяет изолированную функцию или модуль, быстрый. E2E проверяет пользовательский сценарий в реальном браузере против работающего приложения, медленнее и дороже. Между ними — интеграционные тесты компонентов.
</details>

<details><summary>Что такое мок и зачем он нужен?</summary>

Подмена зависимости контролируемой реализацией (сеть, время, модуль), чтобы тест был быстрым, детерминированным и проверял нужный сценарий (ошибка сервера, медленный ответ).
</details>

<details><summary>Что такое CI?</summary>

Автоматическая проверка каждого изменения (сборка, тесты, линтеры) при пуше или PR, чтобы ошибки находились рано и main оставался рабочим.
</details>

<details><summary>Зачем нужен `.gitignore` и что в него класть?</summary>

Исключить из репозитория генерируемые и локальные файлы: `node_modules`, `dist`, кэши, `.env` с секретами, файлы IDE. Lock-файл — **не** игнорировать.
</details>

<details><summary>Как посмотреть, почему в проект попала зависимость?</summary>

`npm ls <pkg>`, `pnpm why <pkg>`, `yarn why <pkg>` — покажут цепочку зависимостей.
</details>
