## Теория

### Три разных процесса

| | Минификация | Сжатие при передаче | Обфускация |
|---|---|---|---|
| Цель | меньше байт и быстрее парсинг | меньше байт по сети | затруднить чтение кода |
| Где | при сборке | сервер или CDN, заголовок `Content-Encoding` | при сборке, после минификации |
| Результат | валидный JS, тот же смысл | тот же файл после распаковки | валидный JS, тот же смысл, но запутанный |
| Размер | −40…70 % | −60…80 % от минифицированного | **растёт**, часто в разы |
| Скорость выполнения | та же или выше | та же | ниже |

Минификацию и сжатие применяют вместе всегда. Обфускацию — редко и точечно.

### Что делает минификатор

```js
// До
function calculateTotal(items, discount) {
  // считаем сумму
  const total = items.reduce((sum, item) => sum + item.price, 0);
  if (process.env.NODE_ENV !== 'production') {
    console.log('total', total);
  }
  return discount === true ? total * 0.9 : total;
}

// После (форматирование оставлено для читаемости)
function calculateTotal(e, t) {
  const r = e.reduce((e, t) => e + t.price, 0);
  return !0 === t ? .9 * r : r;
}
```

Три слоя работы:

1. **Удаление лишнего** — пробелы, переводы строк, комментарии, лишние скобки и точки с запятой.
2. **Compress** — переписывание выражений: свёртка констант (`60 * 60` → `3600`), удаление недостижимого кода (`if (false) {...}`), инлайнинг одноразовых переменных и функций, `true` → `!0`, `undefined` → `void 0`, `if` → `&&` или тернарный оператор.
3. **Mangle** — переименование **локальных** идентификаторов в короткие (`items` → `e`). Глобальные имена, экспорты верхнего уровня (если модуль не склеен сборщиком) и свойства объектов по умолчанию не трогаются: их могут читать снаружи.

Имя `calculateTotal` осталось, потому что это функция верхнего уровня скрипта. В ES-модуле, который сборщик склеил с остальными (scope hoisting), переименуется и она.

💡 **На собеседовании:** минификатор работает с AST, а не с текстом — поэтому он знает области видимости и может безопасно переименовывать. Регулярками так не сделать: строки, шаблоны и регулярные выражения содержат символы, похожие на код.

### Удаление мёртвого кода: `define` и `PURE`

Минификатор удаляет код, только если **доказал**, что тот не нужен. Сборщик ему помогает:

```js
// vite.config.ts / webpack DefinePlugin: process.env.NODE_ENV заменяется строкой
if (process.env.NODE_ENV !== 'production') { warnAboutKeys(); }
// → if ('production' !== 'production') {...} → if (false) {...} → удалено
```

Так из React и Vue уходят предупреждения режима разработки. Если библиотека читает `process.env.NODE_ENV` через переменную (`const env = process.env; if (env.NODE_ENV ...)`), замена не сработает и dev-код останется в бандле.

```js
export const Button = /*#__PURE__*/ createComponent('button');
```

`/*#__PURE__*/` перед вызовом говорит: «у вызова нет побочных эффектов, если результат не используется — удаляй». Без пометки минификатор обязан оставить вызов: вдруг `createComponent` что-то регистрирует глобально. Связь с tree shaking и `sideEffects` — в [оптимизации бандла](03-bundle-optimization.md).

Удаление отладки в продакшене:

```js
// esbuild / Vite
esbuild: { drop: ['console', 'debugger'] }        // удалить все console.* и debugger
esbuild: { pure: ['console.log', 'console.debug'] } // удалить только эти, если результат не нужен

// Terser
terserOptions: { compress: { drop_console: true, pure_funcs: ['console.debug'] } }
```

🪤 **Ловушка:** `drop: ['console']` удаляет и `console.error`, которым вы, возможно, пишете в мониторинг. Точечный `pure` безопаснее. А аргументы удалённого вызова тоже не выполнятся: `console.log(track())` потеряет вызов `track()`.

### Минификаторы и где они стоят

| Инструмент | Язык | Где используется |
|---|---|---|
| Terser | JS | webpack (`TerserPlugin` по умолчанию), Vite по опции `build.minify: 'terser'`; медленный, но самый настраиваемый |
| esbuild | Go | Vite до перехода на Rolldown, многие CLI-сборки; очень быстрый |
| SWC minifier | Rust | Next.js, Rspack (`SwcJsMinimizerRspackPlugin`), webpack через `TerserPlugin.swcMinify` |
| Oxc minifier | Rust | Rolldown и Vite на его основе |
| Lightning CSS, cssnano | Rust, JS | минификация CSS: Lightning CSS — Vite и Rspack, cssnano — PostCSS и `css-minimizer-webpack-plugin` |
| html-minifier-terser | JS | минификация HTML, например в `html-webpack-plugin` |

Разница в размере между современными минификаторами — обычно единицы процентов, разница в скорости — до десятков раз. Поэтому индустрия ушла с Terser на нативные инструменты. Terser оставляют, когда нужна тонкая настройка `compress`.

```js
// webpack: свой минимайзер вместо стандартного
optimization: {
  minimize: true,
  minimizer: [
    new TerserPlugin({ minify: TerserPlugin.swcMinify, extractComments: false }),
    new CssMinimizerPlugin(),
  ],
}
```

### Что ломает минификация

| Симптом | Причина | Решение |
|---|---|---|
| Логика по `constructor.name` или `fn.name` работает в dev и ломается в проде | имена классов и функций переименованы | не завязываться на имена; или `keep_classnames` / `keep_fnames` (Terser), `keepNames` (esbuild) |
| Свойство объекта «пропало» | включено переименование свойств (`mangle.properties`), а объект пришёл с сервера или из другого бандла | свойства переименовывать только по явному префиксу (`regex: /^_private_/`) и в одном бандле |
| Код с `eval` или `with` почти не минифицируется | минификатор не может доказать, какие имена используются, и отключает переименование в этой области | не использовать `eval` |
| Разное поведение после `unsafe`-опций | `unsafe`, `pure_getters`, `unsafe_math` предполагают «хороший» код без геттеров с эффектами | включать только с тестами на собранный бандл |
| Сломанные лицензионные комментарии | минификатор удаляет комментарии | `/*! ... */` и `@license` сохраняются по умолчанию; esbuild — `legalComments`, Terser — `extractComments` |

🪤 **Ловушка:** тесты гоняются на исходниках, а в прод уходит минифицированный бандл. Хотя бы smoke e2e нужно запускать на продакшен-сборке (`vite preview`, `next start`) — см. [Playwright](07-playwright.md).

### Sourcemaps: обратная дорога

Sourcemap сопоставляет позиции минифицированного кода исходникам, а поле `names` восстанавливает исходные имена переменных. Поэтому стектрейс из продакшена читаем в Sentry.

- `build.sourcemap: 'hidden'` (Vite) / `devtool: 'hidden-source-map'` (webpack) — карты создаются, но ссылки `//# sourceMappingURL` в бандле нет.
- Карты загружаются в систему мониторинга при деплое и **не публикуются** на CDN.

Опубликованная sourcemap — это ваш исходный код целиком, с комментариями и именами. Это главная утечка, которую обфускация уже не исправит. Подробнее — в [ошибках и мониторинге](../15-production/01-errors-and-monitoring.md).

### Сжатие при передаче

Минифицированный файл сервер дополнительно сжимает. Браузер сообщает, что умеет, а сервер выбирает:

```
GET /assets/index-3f9a1c.js
Accept-Encoding: gzip, deflate, br, zstd

HTTP/2 200
Content-Encoding: br
Vary: Accept-Encoding
```

| Алгоритм | Особенности |
|---|---|
| gzip | поддерживается везде, базовый вариант |
| Brotli (`br`) | на 15–25 % лучше gzip для текста; уровень 11 очень медленный — им сжимают заранее при сборке, на лету — уровни 4–6 |
| Zstandard (`zstd`) | сжатие и распаковка быстрее Brotli при близком размере, хорош для динамических ответов; поддержка в браузерах новее |

- **Статику сжимают при сборке** (`index.js.br`, `index.js.gz` рядом с файлом), сервер отдаёт готовый вариант: nginx `brotli_static on` / `gzip_static on`, CDN — по своим настройкам.
- **Динамические ответы** (HTML с SSR, API) сжимают на лету средним уровнем: высокий уровень съест больше CPU, чем сэкономит сети.
- `Vary: Accept-Encoding` обязателен, иначе кэш (CDN, прокси) отдаст Brotli клиенту, который его не умеет.
- Картинки, видео, шрифты WOFF2 уже сжаты — повторное gzip-сжатие тратит CPU впустую.

💡 **На собеседовании:** бюджеты размера в CI считают в **gzip или Brotli**, а время парсинга — от размера **после распаковки**. Мегабайт JS, который «весит 250 КБ по сети», браузер всё равно парсит и компилирует целиком.

Проверка из консоли: `curl -sI -H 'Accept-Encoding: br, gzip' URL | grep -i content-encoding` (см. [Unix-консоль](../17-debugging-git-team/05-unix-console.md)).

### Обфускация

Обфускатор преобразует код так, чтобы его было трудно понять человеку, но он делал то же самое. Самый известный — `javascript-obfuscator` (плагины для webpack и Rollup).

| Техника | Что делает | Цена |
|---|---|---|
| Переименование в шум | `_0x3a1f`, `_0x5b2c` вместо имён | почти бесплатно, но это и так делает минификатор |
| Массив строк | все строки выносятся в массив, часто закодированный (base64, RC4), и достаются через функцию-декодер | размер и время на каждое обращение к строке |
| Control flow flattening | функция превращается в `while` + `switch` с перемешанными блоками и диспетчером | код в разы больше и заметно медленнее |
| Мёртвый код | вставка неисполняемых веток для запутывания | размер |
| Самозащита и антиотладка | код ломается после форматирования, бесконечные `debugger` при открытых DevTools | мешает и вашим разработчикам с отладкой продакшена |
| Domain lock | код работает только на указанных доменах | обходится правкой проверки |

```js
// До
function isPremium(user) { return user.plan === 'pro'; }

// После обфускации (фрагмент)
var _0x4f2a=['plan','pro'];(function(_0x1b,_0x3c){...})(_0x4f2a,0x1a3);
function _0x2d(_0x5e,_0x1f){_0x5e=_0x5e-0x0;var _0x3b=_0x4f2a[_0x5e];return _0x3b;}
function isPremium(_0x7a){return _0x7a[_0x2d('0x0')]===_0x2d('0x1');}
```

### Границы защиты

Код, который выполняется в браузере пользователя, **принадлежит пользователю**: браузер должен его прочитать, чтобы выполнить. Обфускация только поднимает цену анализа.

- DevTools форматируют код (`{}`), ставят точки останова и показывают значения переменных во время выполнения — расшифрованные строки видны в отладчике.
- Есть автоматические деобфускаторы (например, `webcrack`, `synchrony`): они раскрывают массивы строк, упрощают выражения и убирают типовые приёмы `javascript-obfuscator`.
- Сетевые запросы видны во вкладке Network независимо от того, как запутан код.
- WebAssembly — тоже не защита: модуль можно дизассемблировать и отладить.

Следствия для архитектуры:

- **Секреты в бандле публичны.** Ключи API, токены, «секретные» URL — всё, что попало в клиентскую сборку через `VITE_*` или `NEXT_PUBLIC_*`, видит любой. Секреты живут на сервере, клиент обращается через свой бэкенд.
- **Проверки на клиенте — для удобства, а не для безопасности.** Права доступа, цены, лимиты, «премиум-фичи» проверяет сервер. Клиентская проверка `isPremium` отключается одной правкой в DevTools.
- **Подпись запросов на клиенте** не доказывает, что запрос сделал ваш код: алгоритм и ключ извлекаются. Против ботов работают серверные лимиты, поведенческий анализ, аттестация устройства.

Когда обфускация оправдана: продаваемые JS-виджеты и SDK (лицензирование), скрипты антибот-защиты и сбора отпечатков устройства, браузерные игры (усложнить читы), защита от простого копирования конкурентом. Во всех этих случаях это временный барьер, а не гарантия.

Если обфускация нужна:

- применять **после** минификации и tree shaking и только к чувствительным чанкам, а не ко всему приложению;
- мерить размер и производительность до и после, особенно на слабых устройствах;
- проверить совместимость с CSP: некоторые режимы используют `eval` или `new Function`;
- держать sourcemaps для мониторинга, иначе ошибки из обфусцированного чанка не разобрать.

## Вопросы с собеседований

<details><summary>Чем минификация отличается от обфускации?</summary>

Минификация уменьшает размер и ускоряет загрузку: убирает пробелы и комментарии, упрощает выражения, укорачивает локальные имена. Читаемость падает как побочный эффект. Обфускация специально запутывает код — массивы закодированных строк, перемешанный поток управления, — и при этом код становится больше и медленнее. Минификация нужна всегда, обфускация — редко и точечно.
</details>

<details><summary>Если код минифицирован, нужно ли ещё включать gzip или Brotli?</summary>

Да, это разные уровни. Минификатор убирает избыточность синтаксиса, а алгоритм сжатия — повторяющиеся последовательности байт. Вместе они дают лучший результат. Статику лучше сжимать Brotli заранее при сборке на высоком уровне, динамические ответы — на лету средним уровнем. Обязателен `Vary: Accept-Encoding`.
</details>

<details><summary>Почему после минификации сломалась логика, которая работала в dev?</summary>

Частые причины: код опирается на `constructor.name` или `fn.name`, а имена переименованы; включено переименование свойств, а объект пришёл извне; использованы `unsafe`-опции compress. Решение — не завязывать логику на имена, сохранять имена опциями `keep_classnames`/`keepNames` там, где нужно, и прогонять smoke e2e на продакшен-сборке.
</details>

<details><summary>Как убрать dev-код библиотеки из продакшен-бандла?</summary>

Сборщик через `define` подставляет строку вместо `process.env.NODE_ENV`, условие превращается в `if (false)`, и минификатор удаляет ветку. Для вызовов без побочных эффектов помогает `/*#__PURE__*/` и `sideEffects: false` в `package.json`. Если dev-код остался — проверить, как библиотека читает переменную окружения, и посмотреть бандл анализатором.
</details>

<details><summary>Можно ли защитить фронтенд-код от копирования и анализа?</summary>

Нет, только усложнить. Браузер обязан получить и выполнить код, а DevTools и деобфускаторы позволяют его разобрать. Поэтому секретов в бандле быть не должно, бизнес-правила и проверки прав выполняет сервер. Обфускация оправдана как временный барьер: продаваемые SDK, антибот-скрипты, игры. И она имеет цену: размер, скорость, сложная отладка.
</details>

<details><summary>Почему мы видим читаемый стектрейс в Sentry, если код минифицирован?</summary>

При сборке создаются sourcemaps с сопоставлением позиций и исходными именами (`names`). Их загружают в Sentry при деплое, а в публичный бандл ссылку не добавляют (`hidden`). Sentry по номеру релиза находит нужную карту и разворачивает стектрейс.
</details>

<details><summary>Чем Terser отличается от esbuild, SWC и Oxc и что выбрать?</summary>

Terser написан на JS: медленный, но самый настраиваемый. esbuild (Go), SWC и Oxc (Rust) быстрее в десятки раз при близком размере результата, поэтому их ставят по умолчанию Vite, Next.js и Rspack. Менять минификатор стоит, только если измерения показывают выигрыш, или нужна конкретная опция Terser.
</details>

<details><summary>Почему бюджет бандла считают в gzip, но при этом говорят, что важен размер без сжатия?</summary>

Сжатый размер определяет время загрузки по сети. А парсинг, компиляция и выполнение работают с распакованным кодом: 1 МБ JS, который передался как 250 КБ, всё равно нужно разобрать целиком в главном потоке. Поэтому в CI смотрят оба числа, а для метрик главного потока — размер после распаковки.
</details>

<details><summary>Как сервер выбирает сжатие для ответа?</summary>

Браузер присылает `Accept-Encoding` со списком алгоритмов и необязательными весами `q`. Сервер выбирает поддерживаемый алгоритм с наибольшим весом, при равных — по своему приоритету (обычно `zstd`/`br`, затем `gzip`). `q=0` запрещает алгоритм. Ответ помечается `Content-Encoding`, а `Vary: Accept-Encoding` разделяет варианты в кэше.
</details>

<details><summary>Lead: продакт просит «зашифровать фронтенд», чтобы конкуренты не скопировали фичу. Что ответите?</summary>

Объясню, что полностью защитить клиентский код нельзя, и выясню, от чего на самом деле защищаемся. Если от копирования алгоритма — перенести его на сервер и отдавать результат. Если от злоупотреблений API — серверные лимиты, авторизация, мониторинг аномалий. Если нужен барьер для простого копирования — обфусцировать один чувствительный чанк, измерив цену по размеру и скорости. Решение оформлю как ADR с компромиссами.
</details>

## Практика

1. Соберите проект с `build.minify: false`, затем с минификацией по умолчанию и с `'terser'`. Сравните размер в байтах, gzip и Brotli и время сборки.
2. Найдите в бандле dev-код: добавьте ветку `if (import.meta.env.DEV)` и убедитесь, что в продакшен-сборке её нет.
3. Напишите код с `class Foo {}` и проверкой `obj.constructor.name === 'Foo'`, соберите и посмотрите, что сломалось. Почините без `keep_classnames`.
4. Обфусцируйте небольшой файл через `javascript-obfuscator` с `controlFlowFlattening` и `stringArray`, сравните размер и скорость. Затем откройте результат в DevTools и найдите расшифрованную строку в отладчике.
5. Проверьте `curl -I` с разными `Accept-Encoding`, какое сжатие отдаёт ваш продакшен для JS и HTML и есть ли `Vary`.

Тест темы: [Минификация, сжатие и обфускация](../quizzes/quiz.html?id=10-tooling-testing/08-minification-obfuscation).
