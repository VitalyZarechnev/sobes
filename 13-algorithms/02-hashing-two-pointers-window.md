## Теория

### Хэш-таблица: «запомни, что видел»

Сигнал: в брутфорсе есть вложенный цикл, который **ищет** элемент («есть ли пара», «встречалось ли раньше», «сколько раз»). Заменяем поиск O(n) на `Map`/`Set` O(1) — платим O(n) памяти.

```js
// Two Sum: индексы двух чисел с суммой target. O(n) время, O(n) память
function twoSum(nums, target) {
  const indexByValue = new Map();
  for (const [i, x] of nums.entries()) {
    const j = indexByValue.get(target - x);
    if (j !== undefined) return [j, i];
    indexByValue.set(x, i); // кладём ПОСЛЕ проверки, чтобы не взять элемент дважды
  }
  return [];
}
```

Частые ключи: само значение, «дополнение» (`target - x`), **сигнатура** группы (отсортированная строка для анаграмм, счётчик букв `'a1b2…'`), кортеж координат в строке (`` `${r},${c}` ``).

```js
// Группировка анаграмм: ключ — отсортированные буквы. O(n · k log k)
const groupAnagrams = (words) => [...Map.groupBy(words, (w) => [...w].sort().join('')).values()];
```

🪤 **Ловушка:** объект как словарь частот — ключ `'__proto__'` или `'constructor'` ломает логику. Используйте `Map` или `Object.create(null)`.

### Два указателя

**Встречные** — на отсортированном массиве или при проверке палиндрома: `left = 0`, `right = n - 1`, сдвигаем один из них по условию. Каждый шаг отбрасывает кандидатов → O(n).

```js
// Пара с суммой target в ОТСОРТИРОВАННОМ массиве: O(n) время, O(1) память
function pairSumSorted(nums, target) {
  let left = 0;
  let right = nums.length - 1;
  while (left < right) {
    const sum = nums[left] + nums[right];
    if (sum === target) return [left, right];
    if (sum < target) left++; // нужна сумма больше — двигаем левый вправо
    else right--;
  }
  return [];
}
```

**Однонаправленные (read/write)** — фильтрация «на месте»: `write` указывает, куда положить следующий подходящий элемент (удалить дубликаты в отсортированном массиве, переместить нули в конец).

**Быстрый и медленный** (Floyd) — поиск цикла и середины в связном списке; см. [списки](05-lists-and-trees.md).

### Скользящее окно

Сигнал: «подмассив/подстрока **подряд**», «максимальная/минимальная длина», «не более k различных», «сумма окна размера k».

```js
// Переменное окно: длина самой длинной подстроки без повторов. O(n)
function lengthOfLongestSubstring(s) {
  const lastIndex = new Map();
  let start = 0;
  let best = 0;
  for (let end = 0; end < s.length; end++) {
    const ch = s[end];
    // Если символ уже в окне — сдвигаем левую границу за его прошлое вхождение
    if (lastIndex.has(ch) && lastIndex.get(ch) >= start) start = lastIndex.get(ch) + 1;
    lastIndex.set(ch, end);
    best = Math.max(best, end - start + 1);
  }
  return best;
}
```

Шаблон переменного окна: расширяем `end`, пока окно валидно; когда становится невалидным — сжимаем `start`, обновляя состояние окна (счётчики в Map). Каждый индекс входит и выходит из окна один раз → O(n).

**Фиксированное окно** размера k: при сдвиге прибавляем вошедший элемент и вычитаем вышедший — не пересчитываем сумму заново.

🪤 **Ловушка:** окно работает для «монотонных» условий. Если в массиве есть отрицательные числа, «сумма окна ≥ k» не монотонна при расширении — нужны префиксные суммы.

### Префиксные суммы

`prefix[i]` — сумма первых i элементов. Сумма отрезка `[l, r]` = `prefix[r + 1] - prefix[l]` за O(1) после O(n) подготовки.

```js
// Количество подмассивов с суммой k (числа могут быть отрицательными). O(n)
function subarraySum(nums, k) {
  const countByPrefix = new Map([[0, 1]]); // пустой префикс
  let prefix = 0;
  let count = 0;
  for (const x of nums) {
    prefix += x;
    // Подмассив (j, i] имеет сумму k, если prefix_j = prefix_i - k
    count += countByPrefix.get(prefix - k) ?? 0;
    countByPrefix.set(prefix, (countByPrefix.get(prefix) ?? 0) + 1);
  }
  return count;
}
```

Вариации: префиксные произведения (Product Except Self), двумерные префиксы для сумм прямоугольников, разностный массив для «прибавить x на отрезке» за O(1).

### Как выбрать паттерн

| Признак в условии | Паттерн |
|---|---|
| «найти пару/дополнение», «встречалось ли», частоты | хэш |
| массив отсортирован, «пара/тройка с суммой» | два указателя |
| палиндром, разворот, слияние двух отсортированных | два указателя |
| «подряд идущие», «самый длинный/короткий отрезок с условием» | скользящее окно |
| суммы отрезков, отрицательные числа, «количество подмассивов с суммой» | префикс + хэш |

💡 **На собеседовании:** назовите паттерн вслух («это задача на переменное окно, потому что…») — это показывает систематичность.

## Вопросы с собеседований

<details><summary>Почему в Two Sum элемент кладут в Map после проверки, а не до?</summary>

Чтобы не сложить элемент сам с собой: при `target = 6` и `x = 3` проверка до вставки не найдёт этот же индекс. Дубликаты (`[3, 3]`) при этом работают: первая тройка уже лежит в Map, когда приходит вторая.
</details>

<details><summary>Когда два указателя лучше хэша?</summary>

Когда вход уже отсортирован или его можно отсортировать: O(1) памяти против O(n). Если нужны исходные индексы, а сортировать нельзя — хэш.
</details>

<details><summary>Почему скользящее окно — O(n), хотя внутри есть вложенный while?</summary>

Каждый указатель только растёт и проходит массив не более одного раза: суммарно ≤ 2n сдвигов (амортизированный анализ).
</details>

<details><summary>Почему окно не работает для «подмассив с суммой k» при отрицательных числах?</summary>

Расширение окна может уменьшить сумму, поэтому нельзя решить, сдвигать левую или правую границу. Префиксные суммы + хэш решают задачу за O(n) независимо от знаков.
</details>

<details><summary>Как проверить, что две строки — анаграммы?</summary>

Подсчитать частоты букв одной строки (+1) и второй (−1) в одной Map и проверить, что все счётчики нулевые: O(n). Сортировка — O(n log n). Для Unicode итерировать по кодовым точкам (`for...of`), а не по UTF-16 единицам.
</details>
