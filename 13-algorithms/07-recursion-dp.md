## Теория

### Рекурсия

Функция решает задачу через ту же задачу меньшего размера. Нужны **база** (когда остановиться) и **шаг** (как уменьшить задачу). Каждый вызов занимает фрейм стека: в JS глубина ограничена (~10 000), хвостовая оптимизация на практике есть только в Safari.

### Бэктрекинг

Перебор с откатом: строим решение по шагам, на каждом шаге пробуем варианты, при тупике откатываемся. Сигналы: «все комбинации/перестановки/разбиения», маленькие ограничения (n ≤ 20).

```js
// Все подмножества: на каждом шаге — взять или не взять элемент. O(n · 2ⁿ)
function subsets(nums) {
  const result = [];
  const current = [];
  const backtrack = (i) => {
    if (i === nums.length) {
      result.push([...current]); // копия! current продолжит меняться
      return;
    }
    current.push(nums[i]);
    backtrack(i + 1); // взяли
    current.pop(); // откат
    backtrack(i + 1); // не взяли
  };
  backtrack(0);
  return result;
}
```

**Отсечения** (pruning) — главное ускорение: прекращать ветку, когда сумма уже больше цели, сортировать вход для раннего выхода, пропускать дубликаты (`if (i > start && a[i] === a[i - 1]) continue`).

🪤 **Ловушка:** `result.push(current)` без копии — все элементы результата окажутся одним и тем же (в итоге пустым) массивом.

### Динамическое программирование

DP = рекурсия + **перекрывающиеся подзадачи** + **оптимальная подструктура**. Сигналы: «сколько способов», «минимум/максимум», «можно ли», выбор на каждом шаге влияет на будущее, а жадный выбор не работает.

Рецепт:
1. **Состояние**: что описывает подзадачу (`dp[i]` — ответ для первых i элементов; `dp[i][j]` — для префиксов двух строк).
2. **Переход**: как выразить состояние через меньшие.
3. **База**: тривиальные состояния.
4. **Порядок** вычисления и **ответ**.
5. **Оптимизация памяти**: если `dp[i]` зависит только от `dp[i-1]` и `dp[i-2]` — хватит двух переменных.

```js
// Грабитель: нельзя брать два соседних дома. dp[i] = max(dp[i-1], dp[i-2] + nums[i])
function rob(nums) {
  let prev2 = 0; // dp[i-2]
  let prev1 = 0; // dp[i-1]
  for (const x of nums) {
    [prev2, prev1] = [prev1, Math.max(prev1, prev2 + x)];
  }
  return prev1;
}
```

**Top-down** (мемоизация) — проще написать из рекурсивного определения, вычисляются только нужные состояния, но рекурсия и накладные расходы Map. **Bottom-up** (таблица) — без риска переполнения стека, легче сжать память.

### Классические 2D-задачи

- **LCS** (наибольшая общая подпоследовательность): `dp[i][j] = a[i-1] === b[j-1] ? dp[i-1][j-1] + 1 : max(dp[i-1][j], dp[i][j-1])`.
- **Редакционное расстояние** (Левенштейн): вставка/удаление/замена — нечёткий поиск, «возможно, вы имели в виду».
- **Пути в сетке**: `dp[r][c] = dp[r-1][c] + dp[r][c-1]`.

Фронтенд-связь: diff-алгоритмы (LCS лежит в основе `git diff` и сравнения текстов, алгоритм Майерса), нечёткий поиск в командной палитре, перенос текста по строкам (Knuth–Plass в TeX), разбиение галереи на ряды одинаковой высоты (justified layout), мемоизация в селекторах.

## Вопросы с собеседований

<details><summary>Чем DP отличается от «разделяй и властвуй»?</summary>

В «разделяй и властвуй» подзадачи независимы (сортировка слиянием), в DP они перекрываются и решения переиспользуются. Без мемоизации перекрывающиеся подзадачи дают экспоненту (наивный Фибоначчи).
</details>

<details><summary>Почему жадный алгоритм не работает для размена монет?</summary>

Для номиналов `[1, 3, 4]` и суммы 6 жадно: 4 + 1 + 1 = 3 монеты, оптимум — 3 + 3 = 2. Жадность работает только для «канонических» систем (как реальные монеты). В общем случае — DP: `dp[s] = min(dp[s - coin] + 1)`.
</details>

<details><summary>Top-down или bottom-up?</summary>

Top-down проще вывести из рекурсивного определения и он вычисляет только достижимые состояния. Bottom-up не упирается в стек, обычно быстрее и позволяет сжать память до O(строки) или O(1). На интервью можно начать с мемоизации, затем предложить таблицу.
</details>

<details><summary>Как вычисляется расстояние Левенштейна и где оно полезно во фронтенде?</summary>

`dp[i][j]` — минимальное число правок, чтобы превратить первые i символов `a` в первые j символов `b`: при равных символах — `dp[i-1][j-1]`, иначе 1 + min(удаление, вставка, замена). O(n·m) времени, O(min(n, m)) памяти при хранении двух строк. Применения: подсказки при опечатках, нечёткий поиск, сравнение версий текста.
</details>
