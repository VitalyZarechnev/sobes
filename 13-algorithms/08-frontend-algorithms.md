## Теория

Во фронтенд-интервью «алгоритмическая» секция часто выглядит не как LeetCode, а как **утилита из реального проекта**. Оценивают корректность на граничных случаях, сложность, читаемость и API (отмена, ошибки, типы).

### Плоский список → дерево

Данные с бэкенда (`{ id, parentId }`) — комментарии, категории, оргструктура, меню. Наивно: для каждого узла искать детей фильтром — O(n²). Правильно: один проход с Map `id → узел` — O(n).

```js
function listToTree(items) {
  const byId = new Map(items.map((item) => [item.id, { ...item, children: [] }]));
  const roots = [];
  for (const node of byId.values()) {
    const parent = node.parentId == null ? undefined : byId.get(node.parentId);
    // Узел без найденного родителя считаем корнем (сирота) — уточните у интервьюера
    (parent ? parent.children : roots).push(node);
  }
  return roots;
}
```

Вопросы для уточнения: порядок детей, что делать с сиротами и циклами, мутировать ли вход (здесь — копии).

### Фильтрация дерева

Поиск по дереву меню/файлов: оставить совпавшие узлы **и их предков** (чтобы был виден путь), детей совпавшего узла — по требованию. Post-order: узел остаётся, если совпал сам или остался хоть один потомок.

### Глубокое сравнение и копирование

`deepEqual` — для мемоизации, тестов, «есть ли несохранённые изменения» в форме. Граничные случаи: `NaN`, `+0/-0` (что ожидается?), `Date`, `RegExp`, `Map`/`Set`, массив vs объект с теми же ключами, разные прототипы, **циклические ссылки** (пара уже сравниваемых объектов → считаем равными, чтобы не уйти в бесконечность). Для копирования есть встроенный `structuredClone` (циклы, Map, Set, Date; без функций и прототипов).

### Время: debounce, throttle, backoff

- **debounce** — выполнить после паузы в событиях (поиск по вводу, ресайз). Нужны `cancel()` и `flush()`, корректный `this` и аргументы последнего вызова; опции `leading`/`trailing`.
- **throttle** — не чаще раза в N мс (скролл, mousemove). Альтернатива для визуальных обновлений — `requestAnimationFrame`.
- **Retry с экспоненциальной задержкой и джиттером** — `delay = base · 2^attempt` + случайная добавка, чтобы клиенты не повторяли синхронно (thundering herd); ретраить только идемпотентные запросы и временные ошибки (сеть, 429, 503), уважать `Retry-After` и `AbortSignal`.

### Конкурентность: пул промисов

Загрузить 1000 файлов не более чем по 5 одновременно; порядок результатов — как у входа. Идея: k «воркеров» берут следующий индекс из общего счётчика. Вариации: остановка при первой ошибке или сбор всех (`allSettled`), отмена через `AbortSignal`, приоритеты.

```js
async function mapWithConcurrency(items, limit, fn) {
  const results = new Array(items.length);
  let next = 0;
  const worker = async () => {
    while (next < items.length) {
      const i = next++; // синхронно — гонки нет, JS однопоточный
      results[i] = await fn(items[i], i);
    }
  };
  await Promise.all(Array.from({ length: Math.min(limit, items.length) }, worker));
  return results;
}
```

### Виртуальный список

Рендерим только видимые строки. При одинаковой высоте: `start = floor(scrollTop / h)`. При разной высоте храним **префиксные суммы** смещений и ищем первую видимую строку **бинарным поиском** — O(log n) на скролл. Плюс overscan (запас строк сверху и снизу), измерение реальных высот (`ResizeObserver`) и коррекция позиции. Готовые решения: TanStack Virtual, react-window, vue-virtual-scroller.

### Дифф списков по ключам

Reconciliation: старый и новый список с ключами → какие элементы удалить, вставить и переместить. Хэш `key → индекс` даёт O(n) на поиск соответствий; минимальное число **перемещений** = n − длина наибольшей возрастающей подпоследовательности старых индексов (Vue 3 использует LIS; React — более простой проход слева направо с `lastPlacedIndex`). Отсюда практический вывод: ключи должны быть стабильными, а индекс в качестве ключа ломает состояние при вставке в начало.

### Нечёткий поиск

Командная палитра (`Ctrl+K`): символы запроса должны встречаться в строке **по порядку** (подпоследовательность) — O(n) двумя указателями; ранжирование — бонусы за начало слова, подряд идущие совпадения, регистр. Для опечаток — расстояние Левенштейна ([DP](07-recursion-dp.md)).

## Вопросы с собеседований

<details><summary>Чем debounce отличается от throttle? Приведите примеры.</summary>

Debounce ждёт паузу и вызывает один раз в конце серии (поиск по мере ввода, сохранение черновика, ресайз). Throttle вызывает не чаще раза в интервал во время серии (скролл, drag, отправка позиции курсора). Для анимаций и перерисовок — `requestAnimationFrame`.
</details>

<details><summary>Как построить дерево из 100 000 элементов с parentId быстро?</summary>

Map `id → узел` и один проход: O(n) времени и памяти. Без Map — O(n²) (фильтр детей для каждого узла) — на 10⁵ это 10¹⁰ операций.
</details>

<details><summary>Как ограничить количество одновременных запросов?</summary>

Пул из k воркеров, которые берут задачи из общей очереди (общий индекс), или семафор. Результаты складывать по исходным индексам. Обработка ошибок: прерывать остальные через `AbortController` или собирать статусы как `allSettled`. В браузере по HTTP/1.1 и так не больше ~6 соединений на домен, но лимит нужен для нагрузки на сервер и память.
</details>

<details><summary>Почему индекс — плохой ключ в списках?</summary>

При вставке в начало или сортировке ключи «переезжают» к другим данным: фреймворк переиспользует DOM и состояние компонентов (значение input, фокус) не того элемента, а также делает лишние обновления вместо одного перемещения.
</details>

<details><summary>Как найти первую видимую строку виртуального списка с разной высотой строк?</summary>

Массив префиксных смещений `offsets[i]` (верх строки i) и бинарный поиск последнего `i`, у которого `offsets[i] <= scrollTop`: O(log n). При изменении высоты строки смещения после неё пересчитываются — лениво или через дерево Фенвика для O(log n) обновлений.
</details>
