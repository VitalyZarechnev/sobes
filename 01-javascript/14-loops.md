## Теория

### 1. Карта всех способов перебора

| Конструкция | Что перебирает | `break` / `continue` | `await` внутри | Возвращает |
|---|---|---|---|---|
| `for (let i = 0; i < n; i++)` | что угодно по индексу или условию | ✅ | ✅ (последовательно) | — |
| `while (cond)` | пока условие истинно | ✅ | ✅ | — |
| `do { } while (cond)` | минимум одна итерация | ✅ | ✅ | — |
| `for...of` | **значения** итерируемого: массив, строка, `Map`, `Set`, генератор, `NodeList` | ✅ | ✅ (последовательно) | — |
| `for await...of` | асинхронный итерируемый или массив промисов | ✅ | — (уже ждёт) | — |
| `for...in` | **ключи** (строки) объекта, включая унаследованные перечисляемые | ✅ | ✅ | — |
| `arr.forEach(fn)` | элементы массива (пропускает дыры) | ❌ (`return` = только `continue`) | ❌ (не ждёт) | `undefined` |
| `arr.map / filter / reduce` | элементы массива | ❌ | ❌ (вернут массив промисов) | новое значение |
| `arr.some / every / find` | элементы до первого совпадения | останавливаются сами | ❌ | boolean / элемент |
| `Object.keys / values / entries` + `for...of` | собственные перечисляемые свойства объекта | ✅ | ✅ | — |
| рекурсия | деревья, вложенные структуры | `return` | ✅ | любое |

### 2. Классический for

```js
for (let i = 0; i < items.length; i++) {
  if (items[i] === target) break;   // досрочный выход
  if (items[i] == null) continue;   // пропустить итерацию
}

for (let i = items.length - 1; i >= 0; i--) {} // обратный порядок — удобно, когда удаляете элементы через splice
for (let i = 0; i < n; i += 2) {}              // произвольный шаг
for (let i = 0, j = arr.length - 1; i < j; i++, j--) {} // два указателя
```

Когда нужен: индекс, нестандартный шаг, обратный порядок, два указателя, изменение массива во время обхода, максимальная производительность в горячем коде.

### 3. while и do...while

```js
let node = list.head;
while (node) {          // число итераций заранее неизвестно
  node = node.next;
}

let attempt = 0;
do {
  attempt++;            // тело выполнится хотя бы один раз
} while (!tryConnect() && attempt < 3);
```

### 4. for...of — перебор значений

Работает с любым **итерируемым** объектом (у которого есть `Symbol.iterator`).

```js
for (const char of 'привет') {}                   // символы (по кодовым точкам, эмодзи не ломаются)
for (const [key, value] of map) {}                // пары Map
for (const item of set) {}                        // элементы Set
for (const [i, value] of ['a', 'b'].entries()) {} // нужен индекс? — entries()
for (const [key, value] of Object.entries(obj)) {} // объект не итерируемый — через entries
for (const el of document.querySelectorAll('li')) {} // NodeList итерируемый
```

Обычный объект `{}` **не итерируемый**: `for (const x of {})` → `TypeError: {} is not iterable`.

Плюсы: читаемость, `break`/`continue`, работа с `await`. Это выбор по умолчанию для массивов, когда нужен ранний выход или асинхронность.

### 5. for...in — перебор ключей объекта

```js
const user = { name: 'Аня', age: 30 };
for (const key in user) {
  console.log(key, user[key]);
}
```

🪤 Проблемы `for...in`:
- перебирает и **унаследованные** перечисляемые свойства (если кто-то добавил свойство в прототип — оно появится);
- ключи всегда **строки**;
- для массивов перебирает индексы как строки **и** любые дополнительные свойства. Это медленно и ненадёжно:

```js
const arr = [1, 2, 3];
arr.extra = 'x';
for (const k in arr) console.log(k); // '0', '1', '2', 'extra'
```

Для объектов в современном коде чаще используют `Object.keys`, `Object.values` или `Object.entries` с `for...of`: они берут только собственные свойства.

### 6. forEach и его ограничения

```js
[1, 2, 3].forEach((x, i, arr) => {
  if (x === 2) return;  // 🪤 это не break, а переход к следующему элементу
  console.log(x);
});
```

- **Нельзя прервать**: `break` — синтаксическая ошибка, `return` действует как `continue`. Остановить можно только исключением (плохая практика).
- **Не работает с `await`**:

```js
// 🪤 Не ждёт: все запросы стартуют одновременно, а forEach завершится сразу
ids.forEach(async (id) => {
  await save(id);
});
console.log('готово'); // выведется ДО сохранения
```

Правильные варианты асинхронного перебора:

```js
// Последовательно — по одному
for (const id of ids) {
  await save(id);
}

// Параллельно — все сразу, дождаться всех
await Promise.all(ids.map((id) => save(id)));

// Параллельно, но с ограничением одновременных запросов — пул задач
// (см. promisePool на странице Live-coding)
```

### 7. for await...of

Перебирает **асинхронные итерируемые** объекты: потоки (`ReadableStream`), асинхронные генераторы, пагинацию API.

```js
async function* fetchPages(url) {
  let next = url;
  while (next) {
    const res = await fetch(next);
    const { items, nextUrl } = await res.json();
    yield items;
    next = nextUrl;
  }
}

for await (const items of fetchPages('/api/orders')) {
  render(items); // страница за страницей, по мере загрузки
}
```

### 8. Метки: выход из вложенных циклов

```js
outer: for (const row of matrix) {
  for (const cell of row) {
    if (cell === target) break outer;   // выйти из обоих циклов
    if (cell < 0) continue outer;       // перейти к следующей строке
  }
}
```

Используются редко. Часто код читается проще, если вынести вложенный цикл в функцию и сделать `return`.

### 9. Замыкания в циклах: var против let

```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j)); // 0 1 2
```

`var` создаёт **одну** переменную на функцию, и к моменту срабатывания таймеров цикл уже закончился (`i = 3`). `let` в заголовке `for` создаёт **новую привязку на каждую итерацию**, и каждое замыкание видит своё значение. Подробно — [Замыкания](02-scope-closures-hoisting.md).

### 10. Изменение коллекции во время перебора

```js
const arr = [1, 2, 3];
for (const x of arr) {
  if (arr.length < 5) arr.push(x * 10); // итератор увидит новые элементы
}
// arr = [1, 2, 3, 10, 20]
```

Правила:
- добавление в массив во время `for...of` приводит к тому, что новые элементы будут перебраны (риск бесконечного цикла);
- удаление через `splice` при прямом проходе пропускает элементы: удаляйте в обратном цикле или используйте `filter`;
- для `Map` и `Set` добавленные во время перебора элементы тоже будут посещены.

Лучшая практика — не мутировать коллекцию, по которой идёт перебор, а строить новую.

### 11. Какой цикл быстрее

Замер на массиве из 1 000 000 чисел (суммирование), Node.js 22, среднее из 20 прогонов после прогрева. Абсолютные цифры зависят от машины и версии движка, важны пропорции.

| Способ | Время, мс | Относительно `for` |
|---|---|---|
| `for (let i = 0; i < arr.length; i++)` | ~1.0 | 1× |
| `for` с закэшированной длиной | ~1.0 | 1× — кэширование длины давно не даёт выигрыша, движок делает это сам |
| `while` | ~1.0 | 1× |
| `for...of` | ~6.5 | ~6× |
| `reduce` | ~7 | ~7× |
| `forEach` | ~8 | ~8× |
| `for...in` по массиву | ~67 | ~70× — никогда не используйте для массивов |

Для объекта из 100 000 ключей: `for...in` ≈ 12 мс, `Object.keys` + `for` ≈ 15 мс, `Object.values` + `for...of` ≈ 22 мс, `Object.entries` + `for...of` ≈ 32 мс (`entries` создаёт массив пар).

Что из этого следует:
1. **Разница видна только на сотнях тысяч итераций** с почти пустым телом. 1 млн итераций `forEach` — это 8 мс; в типичном UI-коде (сотни элементов) это микросекунды.
2. Стоимость **тела цикла** (работа с DOM, вызов функций, аллокации) обычно в разы больше стоимости самого цикла.
3. Выбирайте по **семантике и читаемости**: `map`/`filter` для преобразований, `for...of` для раннего выхода и `await`, классический `for` для индексной логики и горячих участков, которые подтвердил профайлер.
4. Сначала профилируйте, потом оптимизируйте. Алгоритмическая сложность (O(n²) → O(n) через `Set`) даёт выигрыш на порядки больше, чем замена `forEach` на `for`.

💡 На собеседовании: «Самый быстрый — классический `for`, `for...of` и методы массивов медленнее в несколько раз из-за итератора и вызова колбэка. Но на реальных объёмах UI это не важно, поэтому я выбираю по читаемости и семантике. Оптимизирую цикл, только если профайлер показал горячий участок, и в первую очередь смотрю на алгоритмическую сложность».

### 12. Рекурсия как способ перебора

Для деревьев (DOM, меню, комментарии) рекурсия естественнее цикла:

```js
function sumTree(node) {
  return node.value + node.children.reduce((sum, child) => sum + sumTree(child), 0);
}
```

Ограничение — глубина стека (порядка 10 000 вызовов). Для очень глубоких структур используют итеративный обход со своим стеком ([Алгоритмы: деревья](../13-algorithms/README.md)). Оптимизация хвостовых вызовов (TCO) есть в спецификации, но реализована только в Safari.

## Вопросы с собеседований

<details><summary>Чем for...of отличается от for...in?</summary>

`for...of` перебирает **значения** итерируемого объекта (массив, строка, `Map`, `Set`, генератор) через `Symbol.iterator`. `for...in` перебирает **строковые ключи** объекта, включая унаследованные перечисляемые свойства. Для массивов `for...in` не подходит: ключи — строки, попадают лишние свойства, порядок не для этого задуман, и он медленный. Для объектов предпочтительнее `Object.entries` с `for...of`.
</details>

<details><summary>Как прервать forEach?</summary>

Никак штатно: `break` недопустим синтаксически, а `return` в колбэке лишь переходит к следующему элементу. Можно бросить исключение, но это плохая практика. Правильно — выбрать другой инструмент: `for...of` с `break`, либо `some`/`every`/`find`/`findIndex`, которые останавливаются сами.
</details>

<details><summary>Почему forEach не работает с async/await?</summary>

`forEach` вызывает колбэк и не ждёт возвращённый промис. Все асинхронные операции стартуют одновременно, а код после `forEach` выполняется сразу, не дожидаясь их, и ошибки не перехватываются. Решения: `for...of` с `await` — последовательно; `Promise.all(arr.map(async ...))` — параллельно; пул с лимитом конкурентности — параллельно с ограничением.
</details>

<details><summary>Почему цикл с var и setTimeout выводит 3 3 3?</summary>

У `var` функциональная область видимости — на весь цикл одна переменная. Колбэки таймеров выполняются после завершения цикла и читают её финальное значение 3. С `let` спецификация создаёт новую привязку на каждую итерацию, и каждое замыкание захватывает своё значение. Старое решение — IIFE с параметром.
</details>

<details><summary>Какой цикл самый быстрый? Имеет ли это значение?</summary>

Классический `for` и `while` быстрее всего, `for...of` и методы массивов медленнее в несколько раз (итератор, вызов колбэка), `for...in` по массиву — в десятки раз. Но разница заметна только на сотнях тысяч итераций с лёгким телом. В реальном коде важнее читаемость и алгоритмическая сложность, а оптимизировать стоит только участки, найденные профайлером.
</details>

<details><summary>Как перебрать объект?</summary>

`for (const [key, value] of Object.entries(obj))` — собственные перечисляемые пары. `Object.keys` и `Object.values` — только ключи или значения. `for...in` — включая унаследованные (обычно нежелательно). `Reflect.ownKeys` — все собственные ключи, включая символы и неперечисляемые. Порядок: сначала целочисленные ключи по возрастанию, потом остальные в порядке добавления.
</details>

<details><summary>Как сделать N запросов последовательно, а как параллельно?</summary>

Последовательно: `for (const id of ids) await load(id);`. Параллельно: `await Promise.all(ids.map(load))` (упадёт на первой ошибке) или `Promise.allSettled` (дождётся всех). Параллельно с ограничением: пул воркеров, каждый из которых берёт следующую задачу из общей очереди. Для потоковых данных — `for await...of`.
</details>

<details><summary>Как безопасно удалять элементы массива в цикле?</summary>

Иммутабельно: `arr = arr.filter(keep)`. Если нужно на месте — идти с конца (`for (let i = arr.length - 1; i >= 0; i--) if (bad(arr[i])) arr.splice(i, 1)`), иначе после удаления индексы сдвигаются и следующий элемент пропускается. Для больших массивов многократный `splice` — O(n²), лучше `filter` или запись «на место» с двумя указателями.
</details>

## Практика

### Предскажите вывод

**1.**
```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j), 0);
```
<details><summary>Ответ</summary>

`3 3 3 0 1 2`
</details>
<details><summary>Почему так</summary>

Сначала завершаются оба цикла, затем выполняются таймеры. Для `var` все колбэки читают одну переменную, которая уже равна 3. Для `let` у каждой итерации своя привязка `j`.
</details>

**2.**
```js
const arr = [1, 2, 3];
arr.extra = 'x';
const keys = [];
for (const k in arr) keys.push(k);
console.log(keys);
```
<details><summary>Ответ</summary>

`['0', '1', '2', 'extra']`
</details>
<details><summary>Почему так</summary>

`for...in` перебирает все перечисляемые строковые ключи, включая добавленное свойство. Индексы тоже приходят строками.
</details>

**3.**
```js
const res = [1, 2, 3].forEach((x) => {
  if (x === 2) return;
  console.log(x);
});
console.log(res);
```
<details><summary>Ответ</summary>

`1`, `3`, `undefined`
</details>
<details><summary>Почему так</summary>

`return` в колбэке `forEach` пропускает только текущую итерацию. Сам `forEach` всегда возвращает `undefined`.
</details>

**4.**
```js
outer: for (let a = 0; a < 3; a++) {
  for (let b = 0; b < 3; b++) {
    if (b === 1) continue outer;
    if (a === 2) break outer;
    console.log(`${a}${b}`);
  }
}
```
<details><summary>Ответ</summary>

`'00'`, `'10'`
</details>
<details><summary>Почему так</summary>

При `a = 0` и `a = 1`: на `b = 0` печать, на `b = 1` переход к следующей итерации внешнего цикла. При `a = 2`, `b = 0` срабатывает `break outer` — выход из обоих циклов.
</details>

**5.**
```js
const log = [];
const wait = (ms, v) => new Promise((r) => setTimeout(() => { log.push(v); r(); }, ms));
[30, 10, 20].forEach(async (ms) => { await wait(ms, ms); });
log.push('после forEach');
setTimeout(() => console.log(log.join(',')), 50);
```
<details><summary>Ответ</summary>

`'после forEach,10,20,30'`
</details>
<details><summary>Почему так</summary>

`forEach` не ждёт промисы: все три таймера стартуют одновременно, строка «после forEach» записывается сразу. Затем таймеры срабатывают в порядке длительности, а не в порядке массива.
</details>

**6.**
```js
let c = 0;
do { c++; } while (false);
let w = 0;
while (false) { w++; }
console.log(c, w);
```
<details><summary>Ответ</summary>

`1 0`
</details>
<details><summary>Почему так</summary>

`do...while` проверяет условие после тела, поэтому тело выполняется минимум один раз. `while` проверяет до тела.
</details>

### Задачи

**1. `findFirstDuplicate(arr)`**

Найдите первый элемент, который встречается в массиве повторно (по порядку второго появления), и **прекратите перебор сразу**, как только он найден. Если дубликатов нет — `undefined`. Сложность O(n).

| Вызов | Результат |
|---|---|
| `findFirstDuplicate([3, 1, 4, 1, 3])` | `1` (его второе появление раньше, чем у 3) |
| `findFirstDuplicate([1, 2, 3])` | `undefined` |

<details><summary>Решение</summary>

```js
function findFirstDuplicate(arr) {
  const seen = new Set();
  for (const x of arr) {
    if (seen.has(x)) return x; // досрочный выход — forEach так не умеет
    seen.add(x);
  }
  return undefined;
}
```
</details>

**2. `mapSequential(items, asyncFn)`**

Обработайте элементы асинхронной функцией **строго по очереди**: следующий вызов начинается только после завершения предыдущего. Верните массив результатов в исходном порядке.

<details><summary>Решение</summary>

```js
async function mapSequential(items, asyncFn) {
  const results = [];
  for (const [index, item] of items.entries()) {
    results.push(await asyncFn(item, index));
  }
  return results;
}
```

`for...of` с `await` даёт последовательное выполнение. `items.map(asyncFn)` запустил бы всё параллельно.
</details>

**3. `removeInPlace(arr, predicate)`**

Удалите из массива **на месте** (не создавая новый массив) все элементы, для которых `predicate` возвращает `true`, за O(n). Верните тот же массив.

<details><summary>Решение</summary>

```js
function removeInPlace(arr, predicate) {
  let write = 0;
  for (let read = 0; read < arr.length; read++) {
    if (!predicate(arr[read])) arr[write++] = arr[read];
  }
  arr.length = write; // обрезаем хвост
  return arr;
}
```

Два указателя: `read` проходит весь массив, `write` указывает, куда записать следующий сохраняемый элемент. Многократный `splice` дал бы O(n²).
</details>

**4. `walkTree(node, visit)` — итеративный обход**

Обойдите дерево `{ value, children: [] }` в глубину (pre-order) **без рекурсии**, вызывая `visit(value)` для каждого узла. Порядок: узел, затем дети слева направо.

<details><summary>Решение</summary>

```js
function walkTree(root, visit) {
  const stack = [root];
  while (stack.length > 0) {
    const node = stack.pop();
    visit(node.value);
    for (let i = node.children.length - 1; i >= 0; i--) stack.push(node.children[i]);
  }
}
```

Дети кладутся в стек в обратном порядке, чтобы первым был извлечён левый. Такой обход не упирается в лимит глубины стека вызовов.
</details>
