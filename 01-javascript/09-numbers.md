## Теория

### 1. Один числовой тип на всё

В JS нет отдельных `int`, `float`, `double`. Тип `number` один, и это **64-битное число с плавающей точкой** по стандарту IEEE-754 (как `double` в C/Java). В нём:

- 1 бит — знак;
- 11 бит — порядок (экспонента);
- 52 бита — мантисса (значащие цифры).

Отсюда все особенности: дробные числа хранятся приближённо, целые точны только до 2^53, есть два нуля, бесконечности и `NaN`.

Для целых произвольной длины есть отдельный тип **`bigint`** (раздел 9).

### 2. Записи чисел

```js
42;          // десятичная
3.14;  .5;  5.;   // дробные, ведущий и хвостовой ноль можно опустить
1e3;         // 1000 — экспоненциальная запись
2.5e-3;      // 0.0025
0xff;        // 255 — шестнадцатеричная
0b1010;      // 10 — двоичная
0o17;        // 15 — восьмеричная
1_000_000;   // 1000000 — разделители для читаемости (только в литералах)
Number('1_000'); // NaN — в строках разделители не работают
```

### 3. Почему 0.1 + 0.2 !== 0.3

Компьютер хранит число в двоичной системе. Дробь `0.1` в двоичной системе бесконечная (как `1/3 = 0.333…` в десятичной), и её приходится округлить до 52 бит мантиссы. Ошибка округления крошечная, но при сложении двух неточных чисел она может стать видимой.

```js
0.1 + 0.2;          // 0.30000000000000004
0.1 + 0.2 === 0.3;  // false
0.1 * 3;            // 0.30000000000000004
(0.1 + 0.7) * 10;   // 7.999999999999999
Math.floor((0.1 + 0.7) * 10); // 7, а не 8 — 🪤 частый баг в расчётах
```

Это не баг JS, а свойство IEEE-754: в Python, Java и C результат такой же.

**Как сравнивать дробные числа** — с допуском (epsilon):

```js
const almostEqual = (a, b, eps = Number.EPSILON) => Math.abs(a - b) < eps;
almostEqual(0.1 + 0.2, 0.3); // true
```

`Number.EPSILON` (≈ 2.2e-16) — разница между 1 и следующим представимым числом. Для больших чисел нужен относительный допуск: `Math.abs(a - b) < eps * Math.max(Math.abs(a), Math.abs(b))`.

**Как считать деньги:** хранить в целых минимальных единицах (копейки, центы) или использовать `BigInt` либо библиотеку десятичной арифметики (decimal.js, big.js). Форматировать — через `Intl.NumberFormat`.

### 4. Границы точности

| Константа | Значение | Смысл |
|---|---|---|
| `Number.MAX_SAFE_INTEGER` | `9007199254740991` (2^53 − 1) | наибольшее целое, которое представимо точно, как и все целые меньше него |
| `Number.MIN_SAFE_INTEGER` | `-9007199254740991` | наименьшее такое целое |
| `Number.MAX_VALUE` | ≈ `1.8e308` | наибольшее конечное число |
| `Number.MIN_VALUE` | `5e-324` | наименьшее **положительное** число (не отрицательное!) |
| `Number.EPSILON` | ≈ `2.2e-16` | шаг между 1 и следующим числом |

После `MAX_SAFE_INTEGER` соседние целые «склеиваются»:

```js
2 ** 53 === 2 ** 53 + 1;        // true
9007199254740993;               // 9007199254740992 — литерал уже округлён
Number.isSafeInteger(2 ** 53);  // false
```

🪤 Ловушка: ID из базы данных типа int64 (например, 64-битные идентификаторы) больше 2^53. `JSON.parse` превращает их в `number` и **молча портит** до того, как ваш код что-то увидит. Решение — передавать такие ID строкой.

### 5. Особые значения: NaN, Infinity, -0

**NaN** («Not a Number») — результат некорректной математической операции: `0 / 0`, `Math.sqrt(-1)`, `Number('abc')`, `undefined + 1`. Свойства:
- `typeof NaN === 'number'`;
- `NaN` не равен ничему, даже себе: `NaN === NaN` → `false`;
- любая арифметика с `NaN` даёт `NaN` («заражает» вычисления);
- любое сравнение с `NaN` (`<`, `>`, `==`) даёт `false`.

**Infinity** — результат переполнения или деления ненулевого числа на ноль: `1 / 0 === Infinity`, `-1 / 0 === -Infinity`, `Number.MAX_VALUE * 2 === Infinity`. Ошибки при делении на ноль в JS нет.

**-0** — отрицательный ноль. Появляется при `-0`, `0 * -1`, `Math.round(-0.4)`. Почти везде неотличим от `0`:

```js
-0 === 0;          // true
String(-0);        // '0'
JSON.stringify(-0); // '0'
Object.is(-0, 0);  // false — единственный «прямой» способ отличить
1 / -0;            // -Infinity — и ещё вот так
Math.sign(-0);     // -0
```

Где `-0` важен: направление движения в анимации (знак скорости при нулевом значении), координаты, сравнение state в React (`Object.is`).

### 6. Проверки: isNaN, isFinite, isInteger

Глобальные `isNaN` и `isFinite` сначала **приводят аргумент к числу**, а методы `Number.*` — нет. Используйте `Number.*`.

| Вызов | Результат | Почему |
|---|---|---|
| `isNaN('abc')` | `true` | `'abc'` приводится к `NaN` |
| `Number.isNaN('abc')` | `false` | строка — не значение `NaN` |
| `isFinite('12')` | `true` | `'12'` → `12` |
| `Number.isFinite('12')` | `false` | строка — не число |
| `Number.isInteger(5.0)` | `true` | `5.0` и `5` — одно и то же число |
| `Number.isInteger('5')` | `false` | строка |
| `Number.isSafeInteger(2 ** 53)` | `false` | за пределами точности |

### 7. Строка → число: Number, parseInt, parseFloat, +

| Способ | `'42'` | `' 42 '` | `'42px'` | `'3.14'` | `''` | `'0x1A'` | `'1e3'` |
|---|---|---|---|---|---|---|---|
| `Number(s)` / `+s` | `42` | `42` | `NaN` | `3.14` | `0` | `26` | `1000` |
| `parseInt(s, 10)` | `42` | `42` | `42` | `3` | `NaN` | `0` | `1` |
| `parseFloat(s)` | `42` | `42` | `42` | `3.14` | `NaN` | `0` | `1000` |

- `Number` и унарный `+` **строгие**: строка должна быть числом целиком. Пустая строка → `0` (🪤 частая ловушка в формах).
- `parseInt` и `parseFloat` **читают префикс** и отбрасывают остальное. Пустая строка или нецифровое начало → `NaN`.
- Всегда передавайте `parseInt` основание: `parseInt(s, 10)`. Без него строка `'0x10'` будет прочитана как 16-ричная.
- `['1', '2', '3'].map(parseInt)` → `[1, NaN, NaN]`: `map` передаёт индекс вторым аргументом, и он становится основанием системы счисления.

Число → строка в другой системе: `(255).toString(16)` → `'ff'`, `(10).toString(2)` → `'1010'`. Обратно: `parseInt('ff', 16)` → `255`.

### 8. Округление и форматирование

| Метод | `2.5` | `-2.5` | `2.7` | `-2.7` | Что делает |
|---|---|---|---|---|---|
| `Math.round` | `3` | `-2` | `3` | `-3` | к ближайшему; ровно `.5` — **вверх**, к +∞ |
| `Math.floor` | `2` | `-3` | `2` | `-3` | вниз, к −∞ |
| `Math.ceil` | `3` | `-2` | `3` | `-2` | вверх, к +∞ |
| `Math.trunc` | `2` | `-2` | `2` | `-2` | отбросить дробную часть, к нулю |

🪤 `Math.round(-2.5)` даёт `-2`, а не `-3`: `.5` всегда округляется к +∞.

**`toFixed(n)`** возвращает **строку** с n знаками после точки и тоже страдает от двоичной неточности:

```js
(1.005).toFixed(2);   // '1.00', а не '1.01' — 1.005 хранится как 1.00499999…
(0.1 + 0.2).toFixed(2); // '0.30'
+(2.345).toFixed(2);  // 2.35 — плюс превращает строку обратно в число
```

Надёжное округление до n знаков для отображения:

```js
const roundTo = (x, n) => Math.round((x + Number.EPSILON) * 10 ** n) / 10 ** n;
roundTo(1.005, 2); // 1.01
```

Для пользователей числа форматируют через **`Intl.NumberFormat`**: он учитывает локаль (разделители групп и дробной части, символ валюты):

```js
new Intl.NumberFormat('ru-RU').format(12345.6789);                // '12 345,679'
new Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' }).format(1234.5); // '1 234,50 ₽'
new Intl.NumberFormat('en-US', { notation: 'compact' }).format(1_250_000); // '1.3M'
new Intl.NumberFormat('ru-RU', { style: 'percent' }).format(0.256); // '26 %'
```

`toPrecision(n)` округляет до n **значащих** цифр: `(123.456).toPrecision(4)` → `'123.5'`.

### 9. Объект Math: шпаргалка

| Метод | Пример | Комментарий |
|---|---|---|
| `Math.max(...arr)`, `Math.min(...arr)` | `Math.max(1, 5, 3)` → `5` | без аргументов: `max()` → `-Infinity`, `min()` → `Infinity`. На очень больших массивах spread может переполнить стек — используйте `reduce` |
| `Math.abs(x)` | `Math.abs(-3)` → `3` | модуль |
| `Math.sign(x)` | `Math.sign(-3)` → `-1` | знак: `-1`, `0`, `-0`, `1`, `NaN` |
| `Math.pow(a, b)` / `a ** b` | `2 ** 10` → `1024` | `**` предпочтительнее |
| `Math.sqrt`, `Math.cbrt` | `Math.cbrt(27)` → `3` | квадратный и кубический корень |
| `Math.hypot(...)` | `Math.hypot(3, 4)` → `5` | длина вектора |
| `Math.random()` | `[0, 1)` | **не криптостойкий**: для токенов используйте `crypto.getRandomValues` или `crypto.randomUUID()` |
| `Math.PI`, `Math.E` | | константы |

Случайное целое в диапазоне `[min, max]` включительно:

```js
const randomInt = (min, max) => Math.floor(Math.random() * (max - min + 1)) + min;
```

**Остаток `%`** берёт знак делимого: `-5 % 3` → `-2`. Для «математического» остатка по модулю (например, индекс в кольцевом буфере): `((n % m) + m) % m`.

**Побитовые операторы** (`|`, `&`, `~`, `<<`, `>>`) приводят числа к 32-битным целым. Отсюда трюки `x | 0` и `~~x` для отбрасывания дробной части — но они ломаются после 2^31: `2 ** 31 | 0` → `-2147483648`. Используйте `Math.trunc`.

### 10. BigInt

**BigInt** — целые числа произвольной длины. Создаются суффиксом `n` или функцией `BigInt()` (без `new`).

```js
const big = 2n ** 64n;              // 18446744073709551616n
BigInt(Number.MAX_SAFE_INTEGER) + 2n; // 9007199254740993n — точно
BigInt('123456789012345678901234567890'); // из строки — без потери точности
typeof 10n;                          // 'bigint'
```

Правила и ограничения:

| Ситуация | Результат |
|---|---|
| `1n + 1` | `TypeError`: нельзя смешивать с `number` в арифметике |
| `1n + BigInt(1)` | `2n` — явное приведение |
| `Number(10n) + 1` | `11` — но большие значения потеряют точность |
| `7n / 2n` | `3n` — деление **отбрасывает** дробную часть (к нулю): `-7n / 2n` → `-3n` |
| `+1n` | `TypeError` — унарный плюс запрещён |
| `Math.max(1n, 2n)` | `TypeError` — `Math` не работает с BigInt |
| `1n < 2`, `2n > 1` | `true` — сравнения смешивать **можно** |
| `1n == 1` | `true` |
| `1n === 1` | `false` — разные типы |
| `JSON.stringify({ a: 1n })` | `TypeError` — нужен `replacer` или строковое представление |
| `0n` в `if` | falsy |

Где применяют: 64-битные идентификаторы, точная денежная арифметика в минимальных единицах, криптография, работа с бинарными протоколами (`DataView.getBigInt64`). BigInt медленнее `number`, поэтому «на всякий случай» его не используют.

## Вопросы с собеседований

<details><summary>Почему 0.1 + 0.2 !== 0.3? Как с этим жить?</summary>

`number` — это 64-битный float по IEEE-754. Дробь `0.1` в двоичной системе бесконечна и округляется до 52 бит мантиссы. Сумма двух неточных значений даёт `0.30000000000000004`. Сравнивать дробные числа нужно с допуском (`Math.abs(a - b) < Number.EPSILON`), деньги — хранить в целых минимальных единицах или считать в decimal-библиотеке, а показывать через `Intl.NumberFormat`.
</details>

<details><summary>Что такое Number.MAX_SAFE_INTEGER и почему это важно на фронтенде?</summary>

2^53 − 1 — граница, до которой все целые представимы точно. Дальше соседние целые совпадают: `2**53 === 2**53 + 1`. На фронтенде это бьёт по 64-битным ID из бэкенда: `JSON.parse` портит их ещё до того, как код их увидит. Решение — передавать такие ID строкой, а для арифметики использовать `BigInt`.
</details>

<details><summary>Чем isNaN отличается от Number.isNaN?</summary>

Глобальный `isNaN` сначала приводит аргумент к числу, поэтому `isNaN('abc')` → `true`, хотя `'abc'` не является значением `NaN`. `Number.isNaN` возвращает `true` только для самого `NaN`, без приведения. Аналогично `isFinite` и `Number.isFinite`. В современном коде — только `Number.*`.
</details>

<details><summary>Чем Number() отличается от parseInt() и parseFloat()?</summary>

`Number` строгий: строка должна быть числом целиком (`'42px'` → `NaN`), пустая строка → `0`, понимает `0x`/`0b`/`0o` и экспоненту. `parseInt`/`parseFloat` читают числовой префикс и отбрасывают хвост (`'42px'` → `42`), пустая строка → `NaN`. `parseInt` без основания ведёт себя неочевидно, поэтому всегда `parseInt(s, 10)`.
</details>

<details><summary>Что такое -0 и где он может всплыть?</summary>

Отрицательный ноль из IEEE-754: `0 * -1`, `Math.round(-0.4)`. `-0 === 0`, в строку выводится как `'0'`, отличить можно через `Object.is(-0, 0)` или `1 / x === -Infinity`. Всплывает в анимациях и физике (знак направления), в графиках, в React (`Object.is` считает смену `0` на `-0` изменением state).
</details>

<details><summary>Почему (1.005).toFixed(2) даёт '1.00'?</summary>

`1.005` в двоичном виде хранится как `1.00499999999999989…`, и `toFixed` честно округляет это значение вниз. Решения: добавить `Number.EPSILON` перед округлением, считать в целых единицах или использовать decimal-библиотеку. Для отображения — `Intl.NumberFormat` с `maximumFractionDigits`.
</details>

<details><summary>Когда нужен BigInt и какие у него ограничения?</summary>

Для целых больше 2^53: 64-битные ID, точная денежная арифметика в копейках, криптография. Ограничения: нельзя смешивать с `number` в арифметике (`TypeError`), не работает `Math`, нельзя унарный `+`, деление отбрасывает дробную часть, `JSON.stringify` бросает ошибку. Работает медленнее `number`.
</details>

<details><summary>Как получить случайное число безопасно?</summary>

`Math.random()` не криптостойкий: годится для UI и игр, но не для токенов, паролей и идентификаторов сессий. Для них — `crypto.getRandomValues(new Uint32Array(1))` или `crypto.randomUUID()`.
</details>

<details><summary>Почему -5 % 3 равно -2? Как получить положительный остаток?</summary>

Оператор `%` в JS — остаток (remainder), а не модуль (modulo): знак результата совпадает со знаком делимого. Для кольцевых индексов нужна формула `((n % m) + m) % m`, которая всегда даёт значение в `[0, m)`.
</details>

<details><summary>Почему x | 0 — плохой способ отбросить дробную часть?</summary>

Побитовые операторы приводят число к 32-битному целому со знаком. Для чисел за пределами ±2^31 результат искажается: `2 ** 31 | 0` → `-2147483648`. Кроме того, это нечитаемо. Правильно — `Math.trunc(x)`.
</details>

## Практика

### Предскажите вывод

**1.**
```js
console.log(0.1 + 0.2 === 0.3, (0.1 + 0.2).toFixed(2) === '0.30');
console.log(Math.floor((0.1 + 0.7) * 10));
```
<details><summary>Ответ</summary>

`false true`, `7`
</details>
<details><summary>Почему так</summary>

Сумма равна `0.30000000000000004`, но `toFixed(2)` округляет до `'0.30'` (строка). `(0.1 + 0.7) * 10` = `7.999999999999999`, а `Math.floor` отбрасывает дробную часть вниз.
</details>

**2.**
```js
console.log(Math.round(2.5), Math.round(-2.5), Math.trunc(-2.7), Math.floor(-2.7));
```
<details><summary>Ответ</summary>

`3 -2 -2 -3`
</details>
<details><summary>Почему так</summary>

`Math.round` округляет `.5` к +∞: `2.5 → 3`, `-2.5 → -2`. `trunc` отбрасывает дробь (к нулю), `floor` — вниз, к −∞.
</details>

**3.**
```js
console.log(isNaN('abc'), Number.isNaN('abc'), isFinite('12'), Number.isFinite('12'));
```
<details><summary>Ответ</summary>

`true false true false`
</details>
<details><summary>Почему так</summary>

Глобальные функции приводят аргумент к числу (`'abc' → NaN`, `'12' → 12`), а методы `Number.*` проверяют без приведения, и строка для них не число.
</details>

**4.**
```js
console.log(9007199254740993, 2 ** 53 === 2 ** 53 + 1);
```
<details><summary>Ответ</summary>

`9007199254740992 true`
</details>
<details><summary>Почему так</summary>

За пределами `MAX_SAFE_INTEGER` шаг между представимыми числами больше 1. Литерал `…993` округляется до ближайшего представимого `…992`, а `2**53 + 1` снова становится `2**53`.
</details>

**5.**
```js
console.log(Math.max(), Math.min(), Math.max(1, NaN), Math.max(1, '3'));
```
<details><summary>Ответ</summary>

`-Infinity Infinity NaN 3`
</details>
<details><summary>Почему так</summary>

Без аргументов `max` начинает с `-Infinity`, а `min` — с `Infinity` (это нейтральные элементы). Любой `NaN` среди аргументов делает результат `NaN`. Строки приводятся к числам.
</details>

**6.**
```js
console.log(5 % 3, -5 % 3, 5 % -3, 5.5 % 2);
```
<details><summary>Ответ</summary>

`2 -2 2 1.5`
</details>
<details><summary>Почему так</summary>

Знак остатка совпадает со знаком **делимого** (левого операнда). `%` работает и с дробными числами.
</details>

**7.**
```js
console.log(7n / 2n, -7n / 2n, 1n == 1, 1n === 1, 1n < 2);
```
<details><summary>Ответ</summary>

`3n -3n true false true`
</details>
<details><summary>Почему так</summary>

Деление BigInt отбрасывает дробную часть в сторону нуля. Нестрогое равенство и сравнения между BigInt и Number разрешены, а строгое равенство различает типы.
</details>

**8.**
```js
console.log(['1', '2', '3'].map(parseInt));
console.log(['1', '2', '3'].map(Number));
```
<details><summary>Ответ</summary>

`[1, NaN, NaN]`, `[1, 2, 3]`
</details>
<details><summary>Почему так</summary>

`map` вызывает колбэк как `(value, index, array)`. `parseInt('1', 0)`: 0 означает «по умолчанию» → `1`. `parseInt('2', 1)`: недопустимое основание → `NaN`. `parseInt('3', 2)`: цифры 3 нет в двоичной системе → `NaN`. `Number` использует только первый аргумент.
</details>

**9.**
```js
console.log(2 ** 31 | 0, ~~-3.7, Math.trunc(-3.7));
```
<details><summary>Ответ</summary>

`-2147483648 -3 -3`
</details>
<details><summary>Почему так</summary>

Побитовые операции превращают число в 32-битное целое со знаком: 2^31 не помещается и «переворачивается» в отрицательное. `~~` и `trunc` для небольших чисел дают одно и то же — отбрасывают дробь к нулю.
</details>

**10.**
```js
console.log(1 / 0, -1 / 0, 0 / 0, 1 / -0, Object.is(-0, 0));
```
<details><summary>Ответ</summary>

`Infinity -Infinity NaN -Infinity false`
</details>
<details><summary>Почему так</summary>

Деление ненулевого числа на ноль даёт бесконечность со знаком, `0 / 0` — `NaN`. Деление на `-0` даёт `-Infinity`: это способ отличить отрицательный ноль. `Object.is` различает `0` и `-0`.
</details>

### Задачи

**1. `almostEqual(a, b, digits?)`**

Напишите функцию сравнения дробных чисел с учётом погрешности.
- Без третьего аргумента — сравнение с допуском `Number.EPSILON`, масштабированным на величину чисел (относительный допуск): `|a − b| ≤ EPSILON × max(|a|, |b|, 1)`.
- С `digits` — числа равны, если совпадают после округления до `digits` знаков после точки.
- `NaN` ни с чем не равен.

| Вызов | Результат |
|---|---|
| `almostEqual(0.1 + 0.2, 0.3)` | `true` |
| `almostEqual(1e20 + 1e4, 1e20)` | `true` (относительная погрешность мала) |
| `almostEqual(1.001, 1.002, 2)` | `true` |
| `almostEqual(1.001, 1.02, 2)` | `false` |
| `almostEqual(NaN, NaN)` | `false` |

<details><summary>Решение</summary>

```js
function almostEqual(a, b, digits) {
  if (Number.isNaN(a) || Number.isNaN(b)) return false;
  if (digits !== undefined) {
    const k = 10 ** digits;
    return Math.round(a * k) === Math.round(b * k);
  }
  const scale = Math.max(Math.abs(a), Math.abs(b), 1);
  return Math.abs(a - b) <= Number.EPSILON * scale;
}
```

Абсолютный допуск `EPSILON` бесполезен для больших чисел: у них шаг между соседними значениями намного больше `2.2e-16`. Поэтому допуск масштабируется на величину.
</details>

**2. `formatMoney(kopecks, currency = 'RUB')`**

Сумма приходит в копейках (целое число). Верните строку для пользователя с правильной локалью `ru-RU`, двумя знаками после запятой и символом валюты. Нельзя делить на 100 с плавающей точкой и потом округлять через `toFixed`.

| Вызов | Результат |
|---|---|
| `formatMoney(123450)` | `'1 234,50 ₽'` |
| `formatMoney(5)` | `'0,05 ₽'` |
| `formatMoney(-99)` | `'-0,99 ₽'` |

<details><summary>Решение</summary>

```js
function formatMoney(kopecks, currency = 'RUB') {
  const formatter = new Intl.NumberFormat('ru-RU', {
    style: 'currency',
    currency,
    minimumFractionDigits: 2,
  });
  // Деление на 100 целого числа даёт число с ≤ 2 знаками; Intl сам округлит корректно.
  return formatter.format(kopecks / 100);
}
```

Деление целого числа копеек на 100 даёт значение с максимум двумя знаками, и `Intl` форматирует его корректно. Ошибки IEEE-754 опасны при *накоплении* операций (сложение множества дробных сумм), поэтому суммировать нужно в копейках, а в рубли переводить только при выводе. Пробелы в результате `Intl` — неразрывные (`U+00A0`/`U+202F`), учитывайте это в тестах.
</details>

**3. `parseUserNumber(input)`**

Пользователь вводит число в поле формы. Напишите разбор, который:
- обрезает пробелы, принимает и запятую, и точку как десятичный разделитель (`'3,14'` → `3.14`);
- игнорирует пробелы-разделители тысяч (`'1 234 567'` → `1234567`);
- для пустой строки возвращает `null` (а не `0`, как `Number('')`);
- для невалидного ввода (`'12abc'`, `'1.2.3'`) возвращает `NaN`.

<details><summary>Решение</summary>

```js
function parseUserNumber(input) {
  const s = input.trim().replace(/[\s  ]/g, '').replace(',', '.');
  if (s === '') return null;
  // Number строгий: '12abc' и '1.2.3' дадут NaN, что нам и нужно
  return Number(s);
}
```

Ключевой момент — не использовать `parseFloat` (он принял бы `'12abc'` как 12) и отдельно обработать пустую строку, которую `Number` превращает в `0`.
</details>

**4. `mod(n, m)` для кольцевого буфера**

Напишите функцию «математического» остатка, который всегда лежит в `[0, m)`. Пример применения — карусель: индекс `-1` должен указывать на последний слайд.

| Вызов | Результат |
|---|---|
| `mod(5, 3)` | `2` |
| `mod(-1, 5)` | `4` |
| `mod(-6, 5)` | `4` |

<details><summary>Решение</summary>

```js
const mod = (n, m) => ((n % m) + m) % m;
```

`n % m` даёт значение в `(-m, m)`. Прибавив `m`, получаем `(0, 2m)`, и повторный `% m` приводит результат в `[0, m)`.
</details>
