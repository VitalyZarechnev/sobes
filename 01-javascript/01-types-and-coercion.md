## Теория

### 1. Что такое тип и как устроена типизация в JS

**Тип** — это множество допустимых значений и операций над ними. Число можно делить, у строки можно взять длину, объект можно расширить свойствами.

JavaScript — язык с **динамической** и **слабой** типизацией:

- **Динамическая**: тип принадлежит *значению*, а не переменной. Одна и та же переменная может хранить сначала число, потом строку. Тип проверяется во время выполнения, а не компиляции (статическую проверку добавляет [TypeScript](../02-typescript/README.md)).
- **Слабая**: при операции над значениями разных типов движок не падает с ошибкой, а **неявно приводит** их к подходящему типу (`'5' * 2 === 10`). Почти вся «магия» и все ловушки этой страницы — следствие слабой типизации.

```js
let value = 42;        // сейчас в переменной число
value = 'сорок два';   // теперь строка — это нормально для JS
value = { n: 42 };     // а теперь объект
```

### 2. Восемь типов: семь примитивов и объект

| Тип | Пример значений | Для чего |
|---|---|---|
| `undefined` | `undefined` | «значение не присвоено»: неинициализированная переменная, отсутствующее свойство, нет `return` |
| `null` | `null` | «значения намеренно нет» — его ставит программист |
| `boolean` | `true`, `false` | логика |
| `number` | `42`, `-0.5`, `NaN`, `Infinity` | все числа: целые и дробные, 64-битный float. Подробно — [Числа](09-numbers.md) |
| `bigint` | `10n`, `2n ** 64n` | целые произвольной длины |
| `string` | `'текст'`, `` `шаблон` `` | текст в UTF-16. Подробно — [Строки и Symbol](10-strings-and-symbols.md) |
| `symbol` | `Symbol('id')` | уникальные идентификаторы-ключи |
| `object` | `{}`, `[]`, `function(){}`, `new Date()`, `new Map()` | всё остальное: структуры, функции, коллекции |

**Примитив** — это неделимое значение без собственных свойств, которое нельзя изменить (иммутабельно). **Объект** — изменяемая коллекция свойств, на которую переменная хранит *ссылку*.

### 3. Значения и ссылки: самое важное различие

Переменная с примитивом хранит само значение. Переменная с объектом хранит ссылку на объект в памяти. Отсюда три следствия.

**Копирование.** При присваивании примитив копируется, а у объекта копируется только ссылка: обе переменные указывают на один объект.

```js
let a = 1;
let b = a;   // скопировали значение
b = 2;
console.log(a); // 1 — a не изменилась

const user = { name: 'Аня' };
const admin = user;   // скопировали ссылку, объект один
admin.name = 'Боря';
console.log(user.name); // 'Боря' — изменили общий объект
```

**Сравнение.** Примитивы сравниваются по значению, объекты — по ссылке (это один и тот же объект или нет).

```js
'abc' === 'abc';  // true — значения равны
{} === {};        // false — два разных объекта
[1, 2] === [1, 2]; // false — по той же причине
const x = {};
x === x;          // true — одна ссылка
```

**Передача в функцию.** Аргументы всегда передаются *по значению*, но для объекта этим значением является ссылка (говорят «call by sharing»). Функция может изменить содержимое объекта, но не может подменить объект в переменной вызывающего кода.

```js
function mutate(obj) { obj.count = 1; }      // меняет общий объект
function replace(obj) { obj = { count: 2 }; } // меняет только локальную переменную

const data = {};
mutate(data);  console.log(data); // { count: 1 }
replace(data); console.log(data); // { count: 1 } — replace не повлиял
```

> Упрощённая модель памяти: примитивы «лежат прямо в переменной», объекты — в куче (heap), а в переменной лежит адрес. Движки (V8) устроены сложнее: короткие целые хранятся как Smi, строки интернируются. Но для рассуждений о коде этой модели достаточно.

### 4. Иммутабельность примитивов и обёртки (autoboxing)

Примитив нельзя изменить, можно только создать новый.

```js
let s = 'hello';
s[0] = 'H';          // молча игнорируется (в strict mode — TypeError)
console.log(s);      // 'hello'
s = 'H' + s.slice(1); // новая строка 'Hello', старая не изменилась
```

Откуда тогда у примитивов методы, например `'abc'.toUpperCase()`? При обращении к свойству движок **временно оборачивает** примитив в объект-обёртку (`String`, `Number`, `Boolean`, `Symbol`, `BigInt`), вызывает метод и выбрасывает обёртку. Это называется autoboxing.

```js
'abc'.length;          // 3 — сработала временная обёртка String
const str = 'abc';
str.custom = 1;        // свойство записалось во временную обёртку…
console.log(str.custom); // undefined — …которая уже уничтожена
```

🪤 Ловушка: обёртки через `new` создают настоящий объект, который ведёт себя неожиданно.

```js
const flag = new Boolean(false);
if (flag) console.log('выполнится!'); // объект всегда truthy
typeof new Number(1); // 'object', а не 'number'
new String('a') === 'a'; // false — объект против примитива
```

`Boolean(x)`, `Number(x)`, `String(x)` **без** `new` — это обычное явное приведение, его использовать можно и нужно.

### 5. Оператор typeof

`typeof x` — унарный оператор, который возвращает **строку** с названием типа значения. Возможных результатов восемь: `'undefined'`, `'boolean'`, `'number'`, `'bigint'`, `'string'`, `'symbol'`, `'object'`, `'function'`.

Он почти совпадает со списком типов, но с двумя аномалиями:
1. `typeof null` возвращает `'object'`, хотя `null` — примитив. Это баг первой версии языка, который нельзя исправить без поломки старых сайтов.
2. Для функций возвращается `'function'`, хотя функция — подвид объекта (объект, который можно вызвать). Это удобное исключение.

Всё остальное «объектное» — массивы, даты, `Map`, регулярные выражения — даёт `'object'`. Поэтому `typeof` хорош для примитивов и функций, но не различает виды объектов (для этого см. раздел 10).

| Выражение | Результат | Комментарий |
|---|---|---|
| `typeof undefined` | `'undefined'` | значение типа undefined |
| `typeof undeclaredVariable` | `'undefined'` | переменная вообще не объявлена — ошибки нет, исторически для проверки наличия API |
| `typeof null` | `'object'` | **аномалия**: баг первой реализации, проверяйте `x === null` |
| `typeof true` | `'boolean'` | логический тип |
| `typeof 42` | `'number'` | целые и дробные — один тип |
| `typeof 3.14` | `'number'` | то же |
| `typeof NaN` | `'number'` | NaN («не число») — особое значение *типа* number |
| `typeof Infinity` | `'number'` | бесконечность — тоже number |
| `typeof 10n` | `'bigint'` | целое произвольной длины |
| `typeof ''` | `'string'` | пустая строка — всё равно строка |
| `typeof 'текст'` | `'string'` | строка |
| `typeof Symbol('id')` | `'symbol'` | уникальный идентификатор |
| `typeof {}` | `'object'` | обычный объект |
| `typeof []` | `'object'` | массив — объект; проверяйте `Array.isArray` |
| `typeof new Date()` | `'object'` | дата — объект |
| `typeof /regex/` | `'object'` | регулярное выражение — объект |
| `typeof new Map()` | `'object'` | коллекции — объекты |
| `typeof Math` | `'object'` | встроенный объект-пространство имён |
| `typeof new Number(1)` | `'object'` | объект-обёртка, а не примитив |
| `typeof function () {}` | `'function'` | функция — вызываемый объект, **аномалия** в нашу пользу |
| `typeof (() => {})` | `'function'` | стрелочная функция |
| `typeof class {}` | `'function'` | класс — это функция-конструктор |
| `typeof async function () {}` | `'function'` | асинхронная функция |
| `typeof function* () {}` | `'function'` | генератор |
| `typeof typeof 1` | `'string'` | `typeof` всегда возвращает строку |
| `typeof x` (x в TDZ) | `ReferenceError` | единственный случай, когда `typeof` бросает ошибку (см. ниже) |

### 6. Временная мёртвая зона (TDZ)

**TDZ** (temporal dead zone) — это участок кода от начала блока до строки с объявлением `let`, `const` или `class`. Переменная в нём уже *существует* (движок знает о ней с момента входа в блок), но ещё *не инициализирована*. Любое обращение к ней в этом участке, даже через `typeof`, бросает `ReferenceError`.

```js
{
  // ── начало TDZ для x ──
  console.log(typeof y); // 'undefined' — y не объявлена нигде, ошибки нет
  console.log(typeof x); // ReferenceError: Cannot access 'x' before initialization
  // ── конец TDZ ──
  let x = 1;
  console.log(x);        // 1
}
```

Сравните с `var`: она «всплывает» (hoisting) и сразу инициализируется значением `undefined`, поэтому ошибки нет, но и пользы тоже.

```js
console.log(a); // undefined — var всплыла с undefined
var a = 1;

console.log(b); // ReferenceError — let всплыла, но в TDZ
let b = 1;
```

TDZ определяется **временем выполнения**, а не положением в тексте. Функция, объявленная выше, может обратиться к переменной, если её *вызовут* после инициализации:

```js
function read() { return value; } // ссылка на value — пока не проблема
// read();  ← здесь вызов дал бы ReferenceError (value ещё в TDZ)
const value = 10;
read(); // 10 — к моменту вызова value инициализирована
```

Менее очевидные места с TDZ:

```js
// Параметры по умолчанию вычисляются слева направо
function f(a = b, b = 1) {} // f() → ReferenceError: b в TDZ при вычислении a

// Затенение: внутренний x уже в TDZ, внешний недоступен
let x = 1;
{
  console.log(x); // ReferenceError — это внутренний x, а не внешний
  let x = 2;
}

// Классы тоже в TDZ
new User(); // ReferenceError
class User {}
```

Зачем TDZ нужна: она превращает ошибку «использовал до присвоения» из тихого `undefined` (как у `var`) в громкое исключение. А для `const` она гарантирует, что значение никогда не будет прочитано до инициализации. Подробнее про области видимости и hoisting — [на следующей странице](02-scope-closures-hoisting.md).

### 7. Приведение типов: явное и неявное

**Приведение типов** (type coercion) — превращение значения одного типа в другой. Бывает:
- **явное** — вы сами вызываете `String(x)`, `Number(x)`, `Boolean(x)`, `parseInt(x)`;
- **неявное** — движок делает это сам внутри операторов: `+`, `-`, `==`, `if (x)`, `` `${x}` ``.

Приведение всегда идёт к одному из трёх типов: **к строке**, **к числу** или **к логическому**. Объект перед этим превращается в примитив (алгоритм ToPrimitive, раздел 9).

| Куда | Явно | Неявно срабатывает в |
|---|---|---|
| К строке (ToString) | `String(x)`, `x.toString()` | `x + ''`, `` `${x}` ``, ключи объектов, `alert(x)` |
| К числу (ToNumber) | `Number(x)`, `+x` | `-`, `*`, `/`, `%`, `**`, `<`, `>`, `<=`, `>=`, `==` с числом, унарный `+` |
| К логическому (ToBoolean) | `Boolean(x)`, `!!x` | `if`, `while`, `? :`, `!`, `&&`, `\|\|` |

### 8. Таблица приведения: ToNumber, ToString, ToBoolean

Главная таблица страницы. В каждой строке все три результата — даже если значение не меняется, это тоже результат, который надо знать.

| Исходное значение | `Number(x)` | `String(x)` | `Boolean(x)` | Почему так |
|---|---|---|---|---|
| `undefined` | `NaN` | `'undefined'` | `false` | «нет значения» не превращается в число |
| `null` | `0` | `'null'` | `false` | «пусто» как ноль — историческое решение |
| `true` | `1` | `'true'` | `true` | |
| `false` | `0` | `'false'` | `false` | |
| `0` | `0` | `'0'` | `false` | ноль — единственное falsy-число кроме `-0` и `NaN` |
| `-0` | `-0` | `'0'` | `false` | при выводе в строку знак минус теряется |
| `NaN` | `NaN` | `'NaN'` | `false` | |
| `Infinity` | `Infinity` | `'Infinity'` | `true` | |
| `''` (пустая строка) | `0` | `''` | `false` | пустая строка → 0 |
| `' '`, `'\n\t'` (пробелы) | `0` | `' '`, `'\n\t'` | **`true`** | пробелы обрезаются → пусто → 0, но строка непустая, значит truthy |
| `'42'` | `42` | `'42'` | `true` | |
| `' 42 '` | `42` | `' 42 '` | `true` | пробелы по краям обрезаются |
| `'4 2'` | `NaN` | `'4 2'` | `true` | пробел внутри — не число |
| `'42px'` | `NaN` | `'42px'` | `true` | `Number` строгий; `parseInt('42px')` даст `42` |
| `'0x1A'`, `'0b101'`, `'0o17'` | `26`, `5`, `15` | без изменений | `true` | понимает 16-, 2- и 8-ричные префиксы |
| `'1e3'` | `1000` | `'1e3'` | `true` | экспоненциальная запись |
| `'.5'`, `'-1.5'` | `0.5`, `-1.5` | без изменений | `true` | |
| `'Infinity'` | `Infinity` | `'Infinity'` | `true` | |
| `'0'` | `0` | `'0'` | **`true`** | непустая строка — truthy, хотя «похожа» на ноль |
| `'false'` | `NaN` | `'false'` | **`true`** | непустая строка — truthy |
| `[]` | `0` | `''` | **`true`** | `[] → '' → 0`, но любой объект truthy |
| `[0]` | `0` | `'0'` | `true` | |
| `[7]` | `7` | `'7'` | `true` | массив из одного элемента → строка элемента |
| `[1, 2]` | `NaN` | `'1,2'` | `true` | `'1,2'` — не число |
| `[null]`, `[undefined]` | `0` | `''` | `true` | `join` превращает `null`/`undefined` в пустую строку |
| `[[1]]` | `1` | `'1'` | `true` | вложенные массивы тоже склеиваются |
| `{}` | `NaN` | `'[object Object]'` | `true` | стандартный `toString` объекта |
| `function () {}` | `NaN` | исходный код функции | `true` | |
| `new Date(0)` | `0` | дата строкой (зависит от часового пояса) | `true` | у `Date` `valueOf` — миллисекунды |
| `Symbol('id')` | **`TypeError`** | `'Symbol(id)'` | `true` | символ нельзя неявно превратить в число или строку, только явно `String()` |
| `10n` | `10` | `'10'` | `true` | |
| `0n` | `0` | `'0'` | `false` | `0n` — falsy |

Запоминать проще по правилам, а не по строкам:
- **К числу:** `undefined → NaN`, `null → 0`, `true/false → 1/0`. Строка обрезается по краям, пустая → `0`, остальное либо число целиком, либо `NaN`. Объект → сначала примитив (ToPrimitive), потом по тем же правилам.
- **К строке:** почти всегда «как написано». Исключения: `-0 → '0'`, массив → элементы через запятую (с `null`/`undefined` как пустые), обычный объект → `'[object Object]'`.
- **К логическому:** запомнить короткий список falsy (раздел ниже). Всё остальное `true`.

### 9. Falsy и truthy

При приведении к логическому типу (в `if`, `while`, `? :`, `!`, `&&`, `||`) значение считается **falsy**, если становится `false`, и **truthy**, если становится `true`.

**Falsy-значений ровно восемь:**

| Значение | Тип |
|---|---|
| `false` | boolean |
| `0` | number |
| `-0` | number |
| `0n` | bigint |
| `''` (пустая строка) | string |
| `null` | null |
| `undefined` | undefined |
| `NaN` | number |

Плюс одно историческое исключение для браузеров: объект `document.all` тоже falsy.

**Truthy — всё остальное.** Список неочевидных truthy, на которых ловят:

| Значение | Почему truthy |
|---|---|
| `true` | очевидно |
| `1`, `-1`, `0.5`, `Infinity`, `-Infinity` | любое число, кроме `0`, `-0` и `NaN`, в том числе отрицательные |
| `'0'`, `'false'`, `' '`, `'null'` | любая **непустая** строка, даже из одного пробела |
| `[]`, `{}` | любой объект, даже пустой |
| `function () {}` | функция — объект |
| `new Boolean(false)`, `new Number(0)` | объекты-обёртки — объекты |
| `Symbol()` | любой символ |
| `1n`, `-1n` | любой bigint, кроме `0n` |
| `new Date(0)` | объект, хотя его числовое значение 0 |

```js
if ([]) console.log('пустой массив truthy');      // выполнится
if ('0') console.log('строка "0" truthy');        // выполнится
if ([].length) console.log('не выполнится');       // 0 — falsy: так правильно проверять пустоту
```

**`&&` и `||` возвращают не boolean, а один из операндов:**
- `a || b` возвращает первый truthy-операнд или последний, если truthy нет;
- `a && b` возвращает первый falsy-операнд или последний, если все truthy;
- `a ?? b` возвращает `b`, только если `a` равен `null` или `undefined`.

```js
'' || 'default';  // 'default'
0 || 10;          // 10 — 🪤 часто ошибка: 0 был валидным значением
0 ?? 10;          // 0  — ?? реагирует только на null/undefined
'a' && 'b';       // 'b' — оба truthy, возвращается последний
null && 'b';      // null — первый falsy
// 0 || null ?? 'x' → SyntaxError: смешивать ?? с || и && без скобок запрещено
```

### 10. ToPrimitive: как объект превращается в примитив

Когда в операции участвует объект, его сначала превращают в примитив. Алгоритм получает **подсказку (hint)** о том, что ожидается: `'string'`, `'number'` или `'default'`.

| Hint | Когда | Пример |
|---|---|---|
| `'string'` | нужен текст | `` `${obj}` ``, `String(obj)`, `obj` как ключ свойства |
| `'number'` | нужна математика | `+obj`, `obj * 2`, `obj < 5`, `Number(obj)` |
| `'default'` | оператор не знает, что нужно | бинарный `obj + x`, `obj == x` |

Шаги:
1. Если у объекта есть метод `[Symbol.toPrimitive]`, вызвать его с hint. Он обязан вернуть примитив, иначе `TypeError`.
2. Иначе вызвать `valueOf` и `toString` по очереди: для `'string'` сначала `toString`, для `'number'` и `'default'` сначала `valueOf`. Берётся первый результат, который оказался примитивом.
3. Если оба метода вернули объекты — `TypeError`.

У обычного объекта `valueOf()` возвращает сам объект (не примитив), поэтому срабатывает `toString()` → `'[object Object]'`. У массива `toString` равен `join(',')`. У `Date` при hint `'default'` порядок как для строки, поэтому `date + 1` даёт строку, а `date - 1` — число.

```js
const money = {
  amount: 42,
  currency: 'USD',
  [Symbol.toPrimitive](hint) {
    return hint === 'string' ? `${this.amount} ${this.currency}` : this.amount;
  },
};
+money;      // 42        (hint 'number')
`${money}`;  // '42 USD'  (hint 'string')
money + 1;   // 43        (hint 'default' → наша функция вернула число)

const legacy = { valueOf() { return 42; }, toString() { return 'obj'; } };
legacy + 1;   // 43    — 'default': сначала valueOf
`${legacy}`;  // 'obj' — 'string': сначала toString
legacy + '';  // '42'  — 'default': valueOf вернул 42, затем склейка со строкой
```

### 11. Операторы и приведение

**Бинарный `+`** — единственный арифметический оператор с двойным смыслом. Оба операнда приводятся к примитиву (hint `'default'`). Если хотя бы один из них строка — получается **конкатенация**, иначе **сложение чисел**.

```js
1 + 2;        // 3
'1' + 2;      // '12'
1 + 2 + '3';  // '33' — слева направо: 1 + 2 = 3, затем 3 + '3'
'1' + 2 + 3;  // '123'
[1] + [2];    // '12' — массивы стали строками '1' и '2'
```

**Остальные арифметические** (`-`, `*`, `/`, `%`, `**`) и **унарный `+`** всегда приводят к числу: `'6' / '2' === 3`, `+'' === 0`.

**Сравнения `<`, `>`, `<=`, `>=`.** Если обе стороны строки — сравниваются лексикографически, посимвольно по кодам UTF-16. Иначе обе приводятся к числу.

```js
'2' > '12';   // true  — строки: символ '2' больше символа '1'
2 > '12';     // false — числа: 2 > 12
'B' < 'a';    // true  — код 'B' (66) меньше кода 'a' (97)
null >= 0;    // true  — null → 0
undefined < 1; // false — undefined → NaN, любое сравнение с NaN ложно
```

### 12. Нестрогое равенство `==` (IsLooselyEqual)

`===` сравнивает без приведения: разные типы — сразу `false`. `==` при разных типах приводит их по правилам:

1. Типы совпадают → работает как `===`.
2. `null == undefined` → `true`. С любым другим значением `null` и `undefined` нестрого **не равны** (никакого приведения к числу!).
3. Число и строка → строка приводится к числу.
4. BigInt и строка → строка приводится к BigInt.
5. Boolean с чем угодно → boolean **сначала** превращается в число (`true → 1`, `false → 0`).
6. Объект и примитив → объект превращается в примитив (ToPrimitive, hint `'default'`), и сравнение повторяется.
7. BigInt и Number → сравниваются математические значения (`1n == 1` → `true`).

```js
'1' == 1;        // true  — правило 3
'true' == true;  // false — правило 5: true → 1; 'true' → NaN; NaN == 1 → false
null == 0;       // false — правило 2, хотя null >= 0 → true
[] == ![];       // true  — ![] → false → 0; [] → '' → 0; 0 == 0
[0] == false;    // true  — хотя [0] truthy и if ([0]) выполнится
NaN == NaN;      // false — NaN не равен ничему, даже себе
```

💡 На собеседовании: «`==` использую осознанно в одном случае — `x == null` как короткую проверку на `null` или `undefined`. В остальном только `===`, и это закреплено линтером (правило `eqeqeq` с опцией `null: 'ignore'`)».

### 13. Три алгоритма равенства

В спецификации есть три способа сказать «равны»:

| Алгоритм | `NaN` и `NaN` | `+0` и `-0` | Где используется |
|---|---|---|---|
| **IsStrictlyEqual** (`===`) | не равны | равны | `===`, `!==`, `indexOf`, `lastIndexOf`, `switch/case` |
| **SameValueZero** | **равны** | равны | `Array.prototype.includes`, `TypedArray.prototype.includes`, ключи `Map` и элементы `Set` |
| **SameValue** (`Object.is`) | равны | **не равны** | `Object.is`, сравнение state и зависимостей в React (`useState`, `useEffect`, `useMemo`) |

```js
[NaN].indexOf(NaN);         // -1   — индекс ищется через ===
[NaN].includes(NaN);        // true — includes использует SameValueZero
new Set([NaN, NaN]).size;   // 1    — Set тоже SameValueZero
new Set([0, -0]).size;      // 1    — нули для Set одинаковы
Object.is(0, -0);           // false
Object.is(NaN, NaN);        // true
```

Подробнее о коллекциях, которые используют SameValueZero, — [Map и Set](13-map-set.md).

### 14. Как надёжно проверить тип значения

| Что проверяем | Надёжный способ | Почему не другой |
|---|---|---|
| `null` | `x === null` | `typeof null === 'object'` |
| `undefined` | `x === undefined` или `typeof x === 'undefined'` (если переменная может быть не объявлена) | |
| `null` **или** `undefined` | `x == null` или `x ?? fallback` | единственное оправданное `==` |
| Примитивы: string, number, boolean, bigint, symbol | `typeof x === 'string'` и т.п. | |
| Число, которое реально число | `typeof x === 'number' && !Number.isNaN(x)` или `Number.isFinite(x)` | `typeof NaN === 'number'` |
| Функция | `typeof x === 'function'` | |
| Массив | `Array.isArray(x)` | `typeof [] === 'object'`; `instanceof Array` ломается между iframe |
| Обычный объект (не null, не массив) | `x !== null && typeof x === 'object' && !Array.isArray(x)` | |
| «Plain object» (литерал `{}`) | `Object.getPrototypeOf(x) === Object.prototype \|\| Object.getPrototypeOf(x) === null` | `class` и `Date` тоже `'object'` |
| Экземпляр своего класса | `x instanceof MyClass` или brand-check `#field in x` | |
| Точное имя встроенного типа | `Object.prototype.toString.call(x)` → `'[object Date]'` | можно подделать через `Symbol.toStringTag`, но работает между iframe |
| Промис / thenable | `typeof x?.then === 'function'` | так «промис» определяет сама спецификация |

**`instanceof`** проходит по цепочке прототипов левого операнда и ищет там `Right.prototype`. Его проблемы:
- у каждого окна (iframe, `node:vm`, worker) свои встроенные конструкторы: массив из iframe — не `instanceof Array` текущего окна;
- с примитивами всегда `false`: `'a' instanceof String`;
- результат можно подделать через `Object.setPrototypeOf` или `Symbol.hasInstance`.

**Optional chaining `?.` и nullish coalescing `??`** — безопасный доступ к данным неизвестной формы:

```js
const city = response?.user?.address?.city ?? 'не указан';
// ?. прерывает цепочку и возвращает undefined, если слева null или undefined
// ?? подставляет значение, только если слева null или undefined (0 и '' сохраняются)
callback?.();           // вызвать, если функция есть
list?.[0];              // взять элемент, если массив есть
```

## Вопросы с собеседований

<details><summary>Сколько типов в JS? Почему typeof null === 'object'?</summary>

Восемь: семь примитивов (`undefined`, `null`, `boolean`, `number`, `bigint`, `string`, `symbol`) и `object`. Функции и массивы — объекты. В первой реализации значения хранились с тегом типа в младших битах; у объектов тег был 0, а `null` был нулевым указателем, и его тег тоже читался как 0. Исправление предлагали, но отклонили: оно сломало бы существующие сайты. Надёжная проверка — `x === null`.
</details>

<details><summary>Чем примитив отличается от объекта? Что значит «передача по ссылке» в JS?</summary>

Примитив иммутабелен, хранится и копируется как значение, сравнивается по значению. Объект изменяем, переменная хранит ссылку, сравнение по ссылке. Строго говоря, в JS всё передаётся по значению, но для объектов значение — это ссылка («call by sharing»). Функция может изменить содержимое переданного объекта, но не может подменить объект в переменной вызывающего кода.
</details>

<details><summary>Как у строки появляются методы, если строка — примитив?</summary>

Autoboxing: при обращении к свойству движок создаёт временный объект-обёртку `String`, вызывает метод и выбрасывает обёртку. Поэтому запись свойства в примитив теряется. Обёртки через `new String(...)` создавать не нужно: это объекты, они truthy и не равны строго своим примитивам.
</details>

<details><summary>Что такое TDZ? Приведите пример.</summary>

Временная мёртвая зона — участок от начала блока до объявления `let`/`const`/`class`. Привязка уже создана, но не инициализирована, поэтому любое чтение, даже `typeof x`, бросает `ReferenceError`. Пример: `{ console.log(x); let x = 1; }`. TDZ зависит от времени выполнения: функция, объявленная до `const`, может читать её, если вызвана после инициализации. Смысл — превратить «использование до присвоения» из тихого `undefined` (`var`) в явную ошибку.
</details>

<details><summary>Перечислите falsy-значения. Truthy ли '0', [] и new Boolean(false)?</summary>

Falsy: `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN` (плюс `document.all`). Всё остальное truthy, включая `'0'`, `'false'`, `' '`, `[]`, `{}` и `new Boolean(false)` — последние три объекты, а любой объект truthy.
</details>

<details><summary>Как вычисляется [] + {} и {} + []?</summary>

`[] + {}`: ToPrimitive обоих (hint `'default'`) даёт `''` и `'[object Object]'`, есть строка — конкатенация → `'[object Object]'`. `{} + []` в начале инструкции (например, в консоли) парсится как пустой блок `{}` и унарный плюс `+[]` → `0`. В позиции выражения (`({} + [])`) — снова `'[object Object]'`. Вывод: важен не только алгоритм приведения, но и грамматика.
</details>

<details><summary>Почему null >= 0 — true, а null == 0 — false?</summary>

Сравнения `<`, `>=` приводят операнды к числу: `null → 0`, и `0 >= 0` истинно. А у `==` отдельное правило: `null` нестрого равен только `undefined` и себе, никакого приведения к числу нет. Мораль: `>=` — это не «`>` или `==`».
</details>

<details><summary>Чем отличаются ===, Object.is и SameValueZero? Где это важно?</summary>

Различаются только на `NaN` и `±0`. `===`: `NaN !== NaN`, `+0 === -0`. `Object.is`: наоборот в обоих случаях. SameValueZero: `NaN` равен себе, нули равны. На практике: `includes` находит `NaN`, а `indexOf` нет; ключи `Map` и элементы `Set` сравниваются по SameValueZero; React сравнивает state и зависимости через `Object.is`.
</details>

<details><summary>Почему instanceof может ошибаться? Чем его заменить?</summary>

Он ищет `Right.prototype` в цепочке прототипов, а у каждого realm (iframe, `node:vm`) свои конструкторы. Прототип можно подменить, а `Symbol.hasInstance` — переопределить. Замены: `Array.isArray`, `Object.prototype.toString.call(x)`, brand-check через приватное поле (`#x in obj`) для своих классов, утиная типизация для протоколов (`typeof x?.then === 'function'`).
</details>

<details><summary>Как сделать объект, который по-разному ведёт себя в числовом и строковом контексте?</summary>

Реализовать `[Symbol.toPrimitive](hint)` или пару `valueOf`/`toString`. `Symbol.toPrimitive` приоритетнее и получает явный hint. Метод обязан вернуть примитив, иначе `TypeError`. Пример из стандартной библиотеки — `Date`. А у `Temporal` `valueOf` специально бросает ошибку, чтобы запретить сравнение через `<`.
</details>

<details><summary>Чем || отличается от ?? и почему их нельзя смешивать?</summary>

`||` возвращает правый операнд, если левый **любой** falsy (`0`, `''`, `false` тоже). `??` — только если левый `null` или `undefined`. Поэтому для значений по умолчанию, где `0` или `''` допустимы, нужен `??`. Смешивать `??` с `||`/`&&` без скобок грамматика запрещает (`SyntaxError`) — чтобы не было путаницы с приоритетом.
</details>

<details><summary>Зачем когда-либо писать ==?</summary>

Почти никогда. Единственный общепринятый случай — `x == null`, короткая проверка «`null` или `undefined`». В остальных случаях `==` скрывает ошибки типов, а правила приведения сложно держать в голове. В команде это фиксируется линтером.
</details>

### Предскажите вывод

Для каждого блока сначала запишите ответ на бумаге, затем откройте «Ответ», а потом «Почему так».

**1. Арифметика со строками**

```js
console.log(1 + '2' - 1);
console.log('3' * '4');
console.log('10' / '2');
console.log('5' - - '2');
```

<details><summary>Ответ</summary>

`11`, `12`, `5`, `7`
</details>
<details><summary>Почему так</summary>

1. `1 + '2'`: есть строка — склейка, получается `'12'`. Затем `'12' - 1`: минус всегда числовой, `12 - 1 = 11`.
2. `*` всегда приводит к числу: `3 * 4`.
3. `/` тоже числовой: `10 / 2`.
4. `- '2'` — унарный минус даёт число `-2`. Затем `'5' - (-2)`: бинарный минус → `5 + 2 = 7`.
</details>

**2. Сложение «всего со всем»**

```js
console.log(true + null + undefined);
console.log(true + true);
console.log('b' + 'a' + +'a' + 'a');
```

<details><summary>Ответ</summary>

`NaN`, `2`, `'baNaNa'`
</details>
<details><summary>Почему так</summary>

1. Строк нет, значит числовое сложение: `true → 1`, `null → 0`, `1 + 0 = 1`; `undefined → NaN`, `1 + NaN = NaN`.
2. `1 + 1 = 2`.
3. `+'a'` — унарный плюс, строка `'a'` не число → `NaN`. Слева направо: `'b' + 'a' = 'ba'`, `'ba' + NaN = 'baNaN'`, `'baNaN' + 'a' = 'baNaNa'`.
</details>

**3. Массивы и нестрогое равенство**

```js
console.log([1] == 1);
console.log([1, 2] == '1,2');
console.log([] == '');
console.log([0] == false);
console.log([] == ![]);
```

<details><summary>Ответ</summary>

`true`, `true`, `true`, `true`, `true`
</details>
<details><summary>Почему так</summary>

Во всех случаях массив сравнивается с примитивом, поэтому он превращается в строку через `join(',')`.
1. `[1] → '1'`, затем `'1' == 1` → строка к числу → `1 == 1`.
2. `[1, 2] → '1,2'`, строки равны.
3. `[] → ''`.
4. `false → 0` (boolean всегда сначала к числу), `[0] → '0' → 0`.
5. Сначала `![]`: массив truthy, значит `false`. Далее `[] == false` → `[] == 0` → `'' == 0` → `0 == 0`.
</details>

**4. null и undefined**

```js
console.log(null + 1, undefined + 1);
console.log(null == 0, null >= 0);
console.log(undefined == 0, null == undefined);
```

<details><summary>Ответ</summary>

`1 NaN`, `false true`, `false true`
</details>
<details><summary>Почему так</summary>

- В арифметике `null → 0`, `undefined → NaN`.
- `null == 0`: у `==` особое правило — `null` равен только `undefined`, приведения к числу нет. А `>=` приводит к числу: `0 >= 0`.
- `undefined == 0` — то же особое правило. `null == undefined` — по этому правилу `true`.
</details>

**5. typeof**

```js
console.log(typeof typeof 1);
console.log(typeof null);
console.log(typeof []);
console.log(typeof NaN);
console.log(typeof class {});
```

<details><summary>Ответ</summary>

`'string'`, `'object'`, `'object'`, `'number'`, `'function'`
</details>
<details><summary>Почему так</summary>

`typeof 1` возвращает строку `'number'`, а `typeof` от строки — `'string'`. `null` — историческая аномалия. Массив — объект. `NaN` — значение типа number. Класс — функция-конструктор.
</details>

**6. Унарный плюс и минус**

```js
console.log('5' + 3, '5' - 3, '5' * '2');
console.log(+'', +' ', +'\n', -'3');
```

<details><summary>Ответ</summary>

`'53' 2 10`, `0 0 0 -3`
</details>
<details><summary>Почему так</summary>

`+` со строкой — склейка, остальные операторы числовые. Пустая строка и строки из одних пробельных символов после обрезки становятся пустыми, а пустая строка → `0`.
</details>

**7. Двойное отрицание**

```js
console.log(!!'0', !!'', !![], !!{});
console.log(!!NaN, !!-1, !!0n, !!new Boolean(false));
```

<details><summary>Ответ</summary>

`true false true true`, `false true false true`
</details>
<details><summary>Почему так</summary>

`!!x` равносильно `Boolean(x)`. Непустая строка `'0'` — truthy, пустая — falsy. Пустые массив и объект — объекты, значит truthy. `NaN` и `0n` — в списке falsy. `-1` — ненулевое число. `new Boolean(false)` — объект-обёртка, а любой объект truthy.
</details>

**8. Логические операторы возвращают операнды**

```js
console.log(0 || 'a');
console.log(0 ?? 'a');
console.log('' && 'b');
console.log('x' && 0 && 'z');
console.log(null || undefined || 0);
```

<details><summary>Ответ</summary>

`'a'`, `0`, `''`, `0`, `0`
</details>
<details><summary>Почему так</summary>

1. `||` ищет первый truthy: `0` falsy, берём `'a'`.
2. `??` срабатывает только на `null`/`undefined`, а `0` — не из них.
3. `&&` возвращает первый falsy: `''`.
4. `'x'` truthy, дальше `0` — первый falsy, на нём остановка.
5. Ни одного truthy — возвращается последний операнд, `0`.
</details>

**9. Сложение объектов**

```js
console.log([] + []);
console.log([] + {});
console.log([1, 2] + [3]);
console.log({} + {});
```

<details><summary>Ответ</summary>

`''`, `'[object Object]'`, `'1,23'`, `'[object Object][object Object]'`
</details>
<details><summary>Почему так</summary>

Каждый объект через ToPrimitive становится строкой: `[] → ''`, `{} → '[object Object]'`, `[1, 2] → '1,2'`, `[3] → '3'`. Раз получились строки, `+` склеивает их. Внутри `console.log(...)` фигурные скобки — выражение-объект, а не блок, поэтому аномалии `{} + []` здесь нет.
</details>

**10. Сравнение строк и чисел**

```js
console.log('2' > '12', 2 > '12');
console.log('a' < 'b', 'B' < 'a');
console.log(null < 1, undefined < 1);
```

<details><summary>Ответ</summary>

`true false`, `true true`, `true false`
</details>
<details><summary>Почему так</summary>

Две строки сравниваются посимвольно: первый символ `'2'` больше `'1'`, дальше не смотрим. Если хоть одна сторона число — обе приводятся к числу: `2 > 12` ложно. `'B'` (код 66) меньше `'a'` (код 97): заглавные латинские буквы идут раньше строчных. `null → 0 < 1`. `undefined → NaN`, а сравнение с `NaN` всегда `false`.
</details>

**11. NaN и коллекции**

```js
console.log(NaN === NaN, Object.is(NaN, NaN));
console.log([NaN].indexOf(NaN), [NaN].includes(NaN));
console.log(new Set([NaN, NaN, 0, -0]).size);
```

<details><summary>Ответ</summary>

`false true`, `-1 true`, `2`
</details>
<details><summary>Почему так</summary>

`===` считает `NaN` неравным себе, `Object.is` — равным. `indexOf` ищет через `===` и не находит, `includes` ищет через SameValueZero и находит. `Set` тоже использует SameValueZero: два `NaN` — один элемент, `0` и `-0` — один элемент. Итого 2.
</details>

**12. Даты**

```js
const d = new Date(0);
console.log(typeof (d + 1), typeof (d - 1), d - 1);
```

<details><summary>Ответ</summary>

`'string' 'number' -1`
</details>
<details><summary>Почему так</summary>

У `Date` при hint `'default'` (бинарный `+`) приоритет у `toString`, получается строка с датой и склейка с `1`. Минус всегда числовой: `valueOf` даты — миллисекунды от эпохи, `0 - 1 = -1`.
</details>

**13. Цепочки сравнений**

```js
console.log(1 < 2 < 3);
console.log(3 > 2 > 1);
console.log(3 > 2 >= 1);
```

<details><summary>Ответ</summary>

`true`, `false`, `true`
</details>
<details><summary>Почему так</summary>

Сравнения выполняются слева направо и возвращают boolean, а не «математическую цепочку». `1 < 2` → `true`, `true < 3` → `1 < 3` → `true`. `3 > 2` → `true`, `true > 1` → `1 > 1` → `false`. `true >= 1` → `1 >= 1` → `true`.
</details>

**14. Явное приведение к числу**

```js
console.log(Number(null), Number(undefined), Number('  '));
console.log(Number([]), Number(['5']), Number({}), Number(false));
```

<details><summary>Ответ</summary>

`0 NaN 0`, `0 5 NaN 0`
</details>
<details><summary>Почему так</summary>

По таблице: `null → 0`, `undefined → NaN`, строка из пробелов → пустая → `0`. Массивы сначала становятся строками: `'' → 0`, `'5' → 5`. Объект → `'[object Object]'` → `NaN`.
</details>

**15. Boolean и ==**

```js
console.log('1' == 1, '1' === 1);
console.log('true' == true, 'false' == false, '1' == true);
```

<details><summary>Ответ</summary>

`true false`, `false false true`
</details>
<details><summary>Почему так</summary>

`===` не приводит типы, разные типы — `false`. В `==` boolean всегда превращается в число первым: `true → 1`, `false → 0`. Тогда `'true' == 1` → `NaN == 1` → `false`. `'false' == 0` → `NaN == 0` → `false`. `'1' == 1` → `true`.
</details>

**16. valueOf против toString**

```js
const o = { valueOf() { return 42; }, toString() { return 'obj'; } };
console.log(o + 1, `${o}`, o + '', String(o), o * 2);
```

<details><summary>Ответ</summary>

`43 'obj' '42' 'obj' 84`
</details>
<details><summary>Почему так</summary>

`o + 1` и `o + ''` — hint `'default'`, первым вызывается `valueOf` → `42`. Дальше `42 + 1 = 43` и `42 + '' = '42'`. Шаблонная строка и `String(o)` — hint `'string'`, первым вызывается `toString` → `'obj'`. `o * 2` — hint `'number'` → `42 * 2`.
</details>

**17. Деление на ноль**

```js
console.log(10 / 0, -10 / 0, 0 / 0, typeof (0 / 0), 10 % 0);
```

<details><summary>Ответ</summary>

`Infinity -Infinity NaN 'number' NaN`
</details>
<details><summary>Почему так</summary>

По стандарту IEEE-754 деление ненулевого числа на ноль даёт бесконечность со знаком, `0 / 0` и остаток от деления на ноль — `NaN`. Ошибки нет. `NaN` — значение типа number. Подробнее — [Числа](09-numbers.md).
</details>

**18. Инкремент строки**

```js
let a = '5';
let b = a++;
console.log(a, typeof a, b, typeof b);
```

<details><summary>Ответ</summary>

`6 'number' 5 'number'`
</details>
<details><summary>Почему так</summary>

`++` всегда числовой: сначала значение приводится к числу (`5`). Постфиксная форма возвращает старое значение **уже как число** — поэтому `b` равен числу `5`, а не строке `'5'`. В `a` записывается `6`.
</details>

**19. Массивы с null и undefined**

```js
console.log(String([null, undefined, 1]));
console.log([null] + 1);
console.log([undefined] == 0, [[]] == 0);
```

<details><summary>Ответ</summary>

`',,1'`, `'1'`, `true true`
</details>
<details><summary>Почему так</summary>

`join` превращает `null` и `undefined` в пустые строки: `',,1'`. `[null] → ''`, затем `'' + 1 = '1'` (строка!). `[undefined] → '' → 0`. `[[]] → [].toString() → '' → 0`.
</details>

**20. parseInt против Number**

```js
console.log(parseInt('08'), parseInt('0x10'), parseInt('12px'), Number('12px'));
console.log(parseFloat('3.14.15'), parseInt(''), Number(''));
```

<details><summary>Ответ</summary>

`8 16 12 NaN`, `3.14 NaN 0`
</details>
<details><summary>Почему так</summary>

`parseInt` читает число с начала строки, пока встречаются допустимые цифры, и отбрасывает хвост: `'12px' → 12`. Префикс `0x` он понимает как 16-ричный. Ведущий ноль больше не означает восьмеричную систему (так было в старых движках). `Number` строгий: вся строка должна быть числом, иначе `NaN`. `parseFloat` останавливается на второй точке. Пустая строка: `parseInt('')` → `NaN`, но `Number('')` → `0`.
</details>

### Задачи

**1. `isSameValueZero(a, b)`**

Реализуйте функцию сравнения двух значений по алгоритму **SameValueZero** — тому, которым пользуются `Array.prototype.includes`, `Map` и `Set`.

Правила SameValueZero:
- значения разных типов не равны;
- `NaN` равен `NaN` (в отличие от `===`);
- `+0` и `-0` равны (в отличие от `Object.is`);
- в остальном — как `===`: примитивы по значению, объекты по ссылке.

Ограничения: нельзя использовать `includes`, `Map`, `Set` и `Object.is`.

| Вызов | Результат |
|---|---|
| `isSameValueZero(1, 1)` | `true` |
| `isSameValueZero('1', 1)` | `false` |
| `isSameValueZero(NaN, NaN)` | `true` |
| `isSameValueZero(0, -0)` | `true` |
| `isSameValueZero({}, {})` | `false` |
| `const o = {}; isSameValueZero(o, o)` | `true` |

<details><summary>Решение</summary>

```js
function isSameValueZero(a, b) {
  // Единственное значение, не равное самому себе, — NaN.
  // Поэтому «a !== a» — надёжная проверка a на NaN без Number.isNaN.
  return a === b || (a !== a && b !== b);
}
```

`===` уже даёт верный ответ во всех случаях, кроме `NaN` (там нужен `true`, а `===` даёт `false`). Нули `===` считает равными, как и требуется. Сложность O(1).
</details>

**2. Сделайте так, чтобы `a == 1 && a == 2 && a == 3` было `true`.**

Нужно объявить переменную `a` так, чтобы условие выполнилось. Изменять само условие нельзя.

<details><summary>Решение</summary>

```js
let i = 1;
const a = { valueOf: () => i++ };
console.log(a == 1 && a == 2 && a == 3); // true
```

Каждое `==` с примитивом вызывает ToPrimitive → `valueOf`, который возвращает следующее число. С `===` этот приём не работает: приведения нет. Пришлось бы определять геттер на глобальном объекте: `Object.defineProperty(globalThis, 'a', { get: () => i++ })`. Вопрос проверяет понимание, что `==` с объектом выполняет пользовательский код.
</details>

**3. `getType(x)` — точное имя типа**

Напишите функцию, которая возвращает строку с точным типом значения в нижнем регистре:
- для примитивов — как `typeof`, но для `null` — `'null'`;
- для объектов — конкретный встроенный тип: `'array'`, `'date'`, `'regexp'`, `'map'`, `'set'`, `'promise'`, `'error'`, `'object'`;
- для функций — `'function'`, `'asyncfunction'`, `'generatorfunction'`;
- должна работать для объектов из другого iframe (то есть без `instanceof`).

| Вызов | Результат |
|---|---|
| `getType(null)` | `'null'` |
| `getType(42)` | `'number'` |
| `getType([])` | `'array'` |
| `getType(new Map())` | `'map'` |
| `getType(async () => {})` | `'asyncfunction'` |
| `getType({})` | `'object'` |

<details><summary>Решение</summary>

```js
function getType(x) {
  if (x === null) return 'null';
  const t = typeof x;
  if (t !== 'object' && t !== 'function') return t; // примитивы
  // '[object Array]' → 'array'
  return Object.prototype.toString.call(x).slice(8, -1).toLowerCase();
}
```

`Object.prototype.toString` читает внутренний тег объекта (или `Symbol.toStringTag`), поэтому работает между iframe. Оговорка: пользовательский класс может подделать тег через `Symbol.toStringTag`.
</details>

**4. `toBoolean`, `toNumber`, `toStr` своими руками**

Реализуйте три функции, которые повторяют `Boolean(x)`, `Number(x)` и `String(x)` **только для примитивов**, без вызова этих встроенных функций, унарного `+` и шаблонных строк. Цель — проговорить таблицу приведения кодом.
- `toBoolean`: вернуть `false` для 8 falsy-значений, иначе `true`.
- `toNumber`: `undefined → NaN`, `null → 0`, boolean → `1`/`0`, строка → обрезать пробелы; пустая → `0`; иначе число или `NaN` (можно использовать `parseFloat` и проверку, что вся строка распарсилась; поддержку `0x` и `Infinity` можно опустить). Число возвращается как есть, symbol → `TypeError`.
- `toStr`: `-0 → '0'`, остальные примитивы → их запись (можно через конкатенацию с `''`, кроме symbol, для него `description`).

<details><summary>Решение</summary>

```js
function toBoolean(x) {
  // Перечисляем falsy явно; x !== x — проверка на NaN
  if (x === false || x === 0 || x === 0n || x === '' || x === null || x === undefined) return false;
  if (x !== x) return false;
  return true;
}

function toNumber(x) {
  if (x === undefined) return NaN;
  if (x === null) return 0;
  if (x === true) return 1;
  if (x === false) return 0;
  if (typeof x === 'number') return x;
  if (typeof x === 'symbol') throw new TypeError('Cannot convert a Symbol value to a number');
  if (typeof x === 'string') {
    const s = x.trim();
    if (s === '') return 0;
    // parseFloat('12px') = 12, а Number требует, чтобы строка была числом целиком,
    // поэтому сначала проверяем формат регулярным выражением
    const isNumeric = /^[-+]?(\d+\.?\d*|\.\d+)(e[-+]?\d+)?$/i.test(s);
    return isNumeric ? parseFloat(s) : NaN;
  }
  throw new TypeError('Только примитивы');
}

function toStr(x) {
  if (typeof x === 'symbol') return `Symbol(${x.description ?? ''})`;
  if (x === 0) return '0'; // и +0, и -0
  return x + '';
}
```

Обратите внимание: `toNumber` не превращает `'12px'` в 12, в отличие от `parseFloat`. Именно эта разница между `Number` и `parseFloat` часто всплывает на собеседованиях.
</details>
