## Вопросы

<details><summary>Что такое React и в чём его основная идея?</summary>

Библиотека для построения UI из компонентов: UI — функция от состояния (`UI = f(state)`). Вы описываете, как должен выглядеть интерфейс, React вычисляет разницу и обновляет DOM. Однонаправленный поток данных: пропсы вниз, события вверх.
</details>

<details><summary>Что такое JSX?</summary>

Синтаксическое расширение, которое компилируется в вызовы `jsx()` (раньше `React.createElement`) и создаёт объекты-элементы. В фигурных скобках — выражения JS. `className`, `htmlFor`, camelCase-атрибуты, обязательный один корень (или фрагмент).
</details>

<details><summary>Чем props отличаются от state?</summary>

Props — входные данные от родителя, только для чтения. State — внутреннее состояние компонента, меняется через сеттер и вызывает повторный рендер. Производные данные не хранят в state — вычисляют при рендере.
</details>

<details><summary>Что такое виртуальный DOM и reconciliation?</summary>

Дерево объектов-элементов, которое React строит при рендере. Reconciliation — сравнение нового дерева с предыдущим (по типу элемента и ключам) и применение минимальных изменений к DOM. Подробно — [рендеринг](01-rendering-reconciliation.md).
</details>

<details><summary>Зачем нужен `key` в списках? Почему индекс — плохой ключ?</summary>

Ключ связывает элемент с его данными между рендерами. Индекс при вставке/удалении/сортировке «переезжает» к другим данным — теряется состояние (input, фокус) и делаются лишние обновления. Ключ — стабильный id из данных.
</details>

<details><summary>Когда компонент перерендеривается?</summary>

При изменении его состояния, при рендере родителя (даже с теми же пропсами, если нет `memo`), при изменении используемого контекста. Перерендер не означает изменение DOM.
</details>

<details><summary>Как работает `useState` и почему обновление «не видно» сразу?</summary>

Сеттер планирует обновление; новое значение будет в следующем рендере, а в текущем замыкании — старое. Для обновлений на основе предыдущего значения — функциональная форма `setCount((c) => c + 1)`. Обновления батчатся.
</details>

<details><summary>Для чего `useEffect` и что такое массив зависимостей?</summary>

Синхронизация с внешними системами (подписки, таймеры, DOM API, запросы без фреймворка) после рендера. Зависимости — значения из рендера, при изменении которых эффект перезапускается; функция очистки вызывается перед повтором и при размонтировании. Не нужен для вычисления данных из пропсов и обработки событий.
</details>

<details><summary>Чем `useMemo`, `useCallback` и `React.memo` отличаются?</summary>

`useMemo` кэширует результат вычисления, `useCallback` — функцию, `React.memo` пропускает рендер компонента при тех же пропсах. Нужны, когда есть измеренная проблема или стабильная ссылка важна (зависимость эффекта, пропс memo-компонента). С React Compiler большая часть ручной мемоизации не нужна. Подробно — [производительность](04-performance.md).
</details>

<details><summary>Что такое `useRef`?</summary>

Изменяемый контейнер `{ current }`, который сохраняется между рендерами и не вызывает рендер при изменении. Для доступа к DOM-элементам и хранения значений вне рендера (id таймера, предыдущее значение).
</details>

<details><summary>Что такое контекст и когда его использовать?</summary>

Передача данных вглубь дерева без props drilling: тема, локаль, текущий пользователь, зависимости. Все потребители перерендериваются при изменении значения — для часто меняющихся данных лучше стор с селекторами.
</details>

<details><summary>Controlled и uncontrolled компоненты?</summary>

Controlled — значение поля в state (`value` + `onChange`). Uncontrolled — значение в DOM (`defaultValue`, `ref`, `FormData`). См. [формы](../16-forms-i18n-auth/01-forms.md).
</details>

<details><summary>Правила хуков?</summary>

Вызывать только на верхнем уровне компонента или кастомного хука (не в условиях и циклах) и только из React-функций. Порядок вызовов — способ, которым React сопоставляет состояние с хуками. Исключение — `use()`, его можно вызывать в условиях.
</details>

<details><summary>Что такое кастомный хук?</summary>

Функция с именем `use*`, которая использует другие хуки и выносит переиспользуемую логику с состоянием (`useDebounce`, `useMediaQuery`). Каждый вызов — независимое состояние.
</details>

<details><summary>Что такое фрагменты и порталы?</summary>

Фрагмент (`<>...</>`) группирует элементы без лишнего DOM-узла. Портал (`createPortal`) рендерит дочерние элементы в другой DOM-узел (модалки, тултипы), сохраняя положение в React-дереве (контекст, всплытие событий).
</details>

<details><summary>Что такое error boundary?</summary>

Компонент, который ловит ошибки рендера потомков и показывает fallback. Пишется классом (`getDerivedStateFromError`, `componentDidCatch`) или через библиотеку `react-error-boundary`. Не ловит ошибки в обработчиках событий и асинхронном коде.
</details>

<details><summary>Что такое Server Components?</summary>

Компоненты, которые выполняются только на сервере (или при сборке): могут читать данные напрямую, не попадают в клиентский бандл, не имеют состояния и эффектов. Интерактивность — в Client Components (`'use client'`). Подробно — [React 19 и RSC](05-react-19-and-server-components.md).
</details>

<details><summary>Как организовать загрузку данных в React-приложении?</summary>

В SPA — TanStack Query/SWR (кэш, дедупликация, состояния loading/error, инвалидация), не голый `useEffect` с `fetch` (гонки, отсутствие кэша). В Next.js — Server Components и Suspense. Подробно — [стейт-менеджеры](10-state-managers-compared.md).
</details>
