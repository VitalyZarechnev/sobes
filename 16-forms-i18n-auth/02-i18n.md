## Теория

### i18n и l10n

**i18n** — подготовка кода к многоязычности (никаких строк в коде, форматирование через локаль, гибкая вёрстка). **l10n** — собственно перевод и адаптация под регион. Локаль — `ru-RU`, `en-US`, `ar-EG` (язык + регион).

### Сообщения: ICU MessageFormat

🪤 **Ловушка:** склейка строк `t('you_have') + count + t('messages')` ломается: порядок слов, падежи и формы множественного числа в языках разные.

```text
# Русский: 4 формы (one, few, many, other)
cart.items = {count, plural,
  =0 {Корзина пуста}
  one {# товар}
  few {# товара}
  many {# товаров}
  other {# товара}
}
greeting = {gender, select, female {Она добавила} male {Он добавил} other {Добавлено}} {item}
```

`Intl.PluralRules('ru').select(21)` → `'one'`, `select(22)` → `'few'`, `select(25)` → `'many'`. Библиотеки: react-intl (FormatJS), i18next (с ICU-плагином или своим форматом), Lingui, next-intl, vue-i18n. Компоненты внутри сообщений (`<b>`, ссылки) — через rich text-интерполяцию, а не разрезание строки.

### Форматирование: Intl

```js
const locale = 'ru-RU';
new Intl.NumberFormat(locale, { style: 'currency', currency: 'RUB' }).format(1234.5); // '1 234,50 ₽'
new Intl.NumberFormat(locale, { notation: 'compact' }).format(1_500_000); // '1,5 млн'
new Intl.NumberFormat(locale, { style: 'unit', unit: 'kilometer-per-hour' }).format(90); // '90 км/ч'
new Intl.DateTimeFormat(locale, { dateStyle: 'long', timeZone: 'Europe/Moscow' }).format(date);
new Intl.RelativeTimeFormat(locale, { numeric: 'auto' }).format(-1, 'day'); // 'вчера'
new Intl.ListFormat(locale, { type: 'conjunction' }).format(['React', 'Vue', 'Svelte']); // 'React, Vue и Svelte'
new Intl.Collator(locale).compare('ёж', 'ель'); // правильная сортировка с «ё»
new Intl.DisplayNames(locale, { type: 'region' }).of('DE'); // 'Германия'
```

Форматтеры дорого создавать — кэшируйте по локали и опциям. Валюта — из данных (заказ в евро показывается в евро), а не из локали пользователя.

### Время и часовые пояса

- Хранить и передавать моменты времени в UTC (ISO 8601 с `Z` или смещением).
- Показывать в часовом поясе пользователя (или объекта: время рейса — в поясе аэропорта).
- Даты без времени (день рождения, дата документа) — не превращать в `Date` с полуночью UTC: в другом поясе получится предыдущий день. Хранить как строку `YYYY-MM-DD` или `Temporal.PlainDate`.
- Арифметика дат (плюс месяц, переход на летнее время) — Temporal (`ZonedDateTime`, `PlainDate`, `Duration`) или date-fns/Luxon. См. [новинки JS](../01-javascript/15-whats-new.md).
- SSR: локаль и часовой пояс сервера и клиента должны совпадать, иначе hydration mismatch — передавать пояс пользователя (cookie) или форматировать время только на клиенте.

### RTL

```css
/* Логические свойства работают и для LTR, и для RTL */
.card {
  margin-inline-start: 16px; /* вместо margin-left */
  padding-inline: 12px;
  border-inline-end: 1px solid var(--color-border);
  text-align: start;
}
```

`<html lang="ar" dir="rtl">`, `dir="auto"` для пользовательского текста неизвестного направления, `<bdi>` для вставок имён. Зеркалировать направленные иконки (стрелки «назад»), но не все (логотипы, иконки воспроизведения — по гайдам). Проверять на псевдолокали.

### Процесс и архитектура

- Ключи по неймспейсам (`checkout.summary.total`), а не текст как ключ (иначе правка текста ломает переводы).
- Ленивая загрузка словарей по языку и маршруту.
- Типизация ключей (генерация типов из базового словаря) — опечатка в ключе = ошибка компиляции.
- TMS (Crowdin, Lokalise, Tolgee) с синхронизацией из CI, контекст и скриншоты для переводчиков.
- CI-проверки: отсутствующие ключи, неиспользуемые ключи, некорректный ICU-синтаксис.
- Псевдолокализация (`[Ŝéţţîñĝš ~~~~]`) — находит захардкоженные строки и вёрстку, которая не выдерживает длинных текстов (+30–40%).
- Локаль в URL (`/en/pricing`) для SEO и шаринга, `hreflang` и `lang`; определение по `Accept-Language` только как начальное предложение.

## Вопросы с собеседований

<details><summary>Как подойти к интернационализации большого React-приложения, включая RTL?</summary>

Библиотека с ICU MessageFormat, ключи по неймспейсам с ленивой загрузкой и типизацией, TMS и проверки в CI, Intl для форматирования, локаль в URL и SSR, логические CSS-свойства и `dir` для RTL, зеркалирование иконок, псевдолокализация и тесты на длинных строках.
</details>

<details><summary>Как форматировать даты, время и числа для разных локалей?</summary>

`Intl.DateTimeFormat`, `NumberFormat`, `RelativeTimeFormat`, `PluralRules`, `ListFormat`, `Collator` с кэшированием форматтеров. Время — в UTC, отображение — в поясе пользователя или объекта; даты без времени — без `Date`. Temporal для арифметики. Совпадение локали и пояса при SSR.
</details>

<details><summary>Почему нельзя склеивать перевод из частей?</summary>

В разных языках разный порядок слов, падежи, род и количество форм множественного числа (в русском 3–4, в арабском 6). Сообщение должно переводиться целиком с параметрами.
</details>
