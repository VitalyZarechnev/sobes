## Теория

### Что такое токен

Дизайн-токен — именованное проектное решение: цвет, отступ, радиус, шрифт, тень, длительность анимации. Токены — единый источник истины для дизайна и кода на всех платформах (web, iOS, Android).

### Три уровня

```text
Примитивы (palette)      →  Семантика (назначение)          →  Компонентные (при необходимости)
blue-600: #2563eb           color-bg-accent: {blue-600}        button-primary-bg: {color-bg-accent}
gray-900: #111827           color-text-primary: {gray-900}     input-border-focus: {color-border-focus}
space-4: 16px               space-inset-md: {space-4}
```

- **Примитивы** — полная палитра и шкалы. Компоненты их **не используют**.
- **Семантические** — что значит значение: фон поверхности, основной текст, опасность, фокус. Темы и бренды переопределяют именно этот уровень.
- **Компонентные** — точечная настройка компонента; вводить только когда нужна независимая кастомизация, иначе их становится тысячи.

Именование: `категория-свойство-вариант-состояние` (`color-bg-danger-hover`, `font-size-body-sm`). Имена описывают **назначение**, а не значение: `color-text-muted`, а не `gray-500`.

### Источник истины и трансформация

```json
{
  "color": {
    "blue": { "600": { "$type": "color", "$value": "#2563eb" } },
    "bg": {
      "accent": { "$type": "color", "$value": "{color.blue.600}" }
    }
  }
}
```

Формат W3C Design Tokens Community Group (`$value`, `$type`, ссылки `{...}`); Figma Variables с режимами (light/dark, бренды) экспортируются в него. Инструменты трансформации (Style Dictionary, Terrazzo) генерируют CSS-переменные, TS-константы, Swift/Kotlin. Процесс: дизайнер меняет переменную → PR с обновлёнными токенами → ревью → новая версия пакета токенов.

### Темы на CSS-переменных

```css
:root {
  color-scheme: light dark;
  /* light-dark() выбирает значение по текущей color-scheme */
  --color-bg-surface: light-dark(#ffffff, #0f172a);
  --color-text-primary: light-dark(#111827, #e5e7eb);
}

/* Явный выбор пользователя поверх системной настройки */
:root[data-theme='light'] { color-scheme: light; }
:root[data-theme='dark'] { color-scheme: dark; }

/* Бренд переопределяет семантический слой */
:root[data-brand='acme'] { --color-bg-accent: #7c3aed; }

.button {
  background: var(--color-bg-accent);
  color: var(--color-text-on-accent);
}
```

Переключение темы — смена атрибута на `<html>`: браузер пересчитывает только переменные, компоненты не перерендериваются.

### Без мигания (FOUC темы)

Тема должна быть известна **до первой отрисовки**:
- Сохранённая тема — в cookie, чтобы SSR сразу отрендерил `data-theme`.
- Для статических сайтов — маленький блокирующий inline-скрипт в `<head>`, который читает `localStorage`/`matchMedia` и ставит атрибут до рендера.
- `color-scheme` и `<meta name="color-scheme">` — чтобы браузер сразу красил фон, скроллбары и поля форм в нужную схему.

### Контраст и доступность в токенах

Проверять пары «текст/фон» семантических токенов автоматически в CI: WCAG 2.2 AA — 4.5:1 для обычного текста, 3:1 для крупного текста и элементов интерфейса. Для пользовательских тем тенантов — генерировать шкалу из бренд-цвета (OKLCH удобен: светлота предсказуема) и проверять контраст при сохранении. `prefers-contrast: more` и `forced-colors: active` (режим высокой контрастности Windows) — отдельные проверки.

### Другие категории токенов

Типографика (семейство, размер, межстрочный интервал, начертание — часто как составной токен), отступы (шкала 4/8), радиусы, тени (elevation), z-index (слои: dropdown, modal, toast), анимации (длительность, easing; уважать `prefers-reduced-motion`), брейкпоинты и размеры контейнеров, плотность интерфейса (compact/comfortable).

## Вопросы с собеседований

<details><summary>Почему компоненты не должны использовать примитивные токены?</summary>

Тогда тема или бренд не смогут поменять смысловое значение: кнопка с `blue-600` останется синей в тёмной теме и в фиолетовом бренде. Семантический слой — точка переопределения: темы меняют `color-bg-accent`, а компоненты об этом не знают.
</details>

<details><summary>Как сделать тёмную тему?</summary>

Семантические токены с разными значениями для схем (CSS-переменные + `light-dark()` или селектор `[data-theme=dark]`), `color-scheme` для системных элементов, выбор по `prefers-color-scheme` с возможностью явного переключения, сохранение выбора, установка темы до первой отрисовки. Проверить контраст, тени (в тёмной теме их заменяет более светлая поверхность), изображения и иллюстрации.
</details>

<details><summary>Как синхронизировать токены между Figma и кодом?</summary>

Единый источник: Figma Variables (экспорт через плагин или REST API) или JSON-токены в репозитории как источник, из которого обновляется Figma. Трансформация в платформы (Style Dictionary/Terrazzo), публикация пакета токенов, ревью изменений как кода, changelog. Ручное копирование hex-значений из макетов — главная причина расхождений.
</details>

<details><summary>Как масштабировать токены на несколько продуктов?</summary>

Общие примитивы и семантика, бренды переопределяют ограниченный набор семантических токенов (акцентные цвета, шрифты, радиусы), продукты используют только семантику. Режимы в Figma Variables для брендов и тем. Количество компонентных токенов держать минимальным.
</details>

## Практика

1. Опишите 10 семантических токенов цвета для light/dark в формате W3C и сгенерируйте CSS-переменные.
2. Сделайте переключатель темы с сохранением в `localStorage` и без мигания при перезагрузке.
3. Напишите скрипт, проверяющий контраст всех пар «текст/фон» ваших токенов.
