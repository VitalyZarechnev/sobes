## Теория

### Цена стороннего кода

Чаты поддержки, виджеты отзывов, аналитика, реклама, A/B-инструменты, карты, видео — часто это больше половины JS страницы и главный источник долгих задач (INP). Сторонний скрипт выполняется с правами вашей страницы: может читать DOM, cookies без `HttpOnly`, перехватывать ввод.

### Загрузка

| Стратегия | Когда |
|---|---|
| `async` | независимые скрипты (аналитика), выполнятся сразу после загрузки |
| `defer` | нужен DOM и порядок, выполнятся после парсинга |
| После `load` / в простое (`requestIdleCallback`) | не критичные для первой отрисовки |
| По взаимодействию — **фасад** | чат, видео, карта: показываем лёгкую заглушку, грузим по клику |
| Web Worker (Partytown) | аналитические теги, которым не нужен синхронный доступ к DOM |
| Сервер (server-side tagging) | события отправляет ваш сервер — меньше JS на клиенте и больше контроля над данными |

`preconnect` к критичным сторонним доменам; в Next.js — `next/script` со стратегиями `beforeInteractive`, `afterInteractive`, `lazyOnload`, `worker`; в Nuxt — Nuxt Scripts с триггерами загрузки.

```js
// Фасад: настоящий виджет чата грузится только по клику
button.addEventListener('click', async () => {
  button.disabled = true;
  await loadScript('https://chat.example.com/widget.js');
  window.ChatWidget.open();
}, { once: true });
```

### Безопасность

- **CSP** с allowlist доменов или nonce/`strict-dynamic`; каждый новый сторонний домен — осознанное решение.
- **SRI** (`integrity`) для версионированных скриптов с CDN; для «вечнозелёных» URL (тег менеджера) невозможно — дополнительный риск.
- **Изоляция**: iframe с `sandbox` для недоверенных виджетов, отдельный поддомен.
- Tag manager даёт маркетингу возможность добавлять скрипты без ревью — нужен процесс согласования.
- Регулярная инвентаризация: что подключено, кто владелец, нужно ли ещё.

### Аналитика: трекинг-план

Трекинг-план — источник истины: событие (`object_action`: `checkout_started`, `filter_applied`), свойства с типами, где срабатывает, владелец, цель.

```ts
// Типы генерируются из трекинг-плана: неверное событие или свойство — ошибка компиляции
type AnalyticsEvents = {
  checkout_started: { cartValue: number; itemsCount: number };
  filter_applied: { filter: 'price' | 'brand'; value: string };
};

export function track<E extends keyof AnalyticsEvents>(event: E, props: AnalyticsEvents[E]): void {
  if (!consent.analytics) return; // уважаем согласие
  queue.push({ event, props, ts: Date.now() });
}
```

- Обёртка над провайдерами: компоненты не знают про Amplitude/Метрику/GA, провайдера можно сменить.
- Батчинг, отправка через `sendBeacon` при скрытии страницы (`visibilitychange` → `hidden`).
- Валидация событий в dev и тесты на ключевые события воронки.
- Ревизия: события, которые никто не смотрит, удаляются.

### Согласие и приватность

GDPR, ePrivacy, 152-ФЗ: необязательные cookies и трекинг — только после согласия; отказ должен быть таким же простым, как согласие; Google Consent Mode и аналоги передают статус согласия тегам; не отправлять PII в аналитику; сроки хранения. Кнопка «Принять всё» не должна быть единственной.

## Вопросы с собеседований

<details><summary>Как загружать сторонние скрипты без блокировки рендеринга?</summary>

Инвентаризация и бюджет, `async`/`defer`, отложенная загрузка после `load` или в простое, фасады для тяжёлых виджетов, перенос в воркер (Partytown) или на сервер, `preconnect`, мониторинг через LoAF/RUM. Плюс безопасность: CSP, SRI, iframe-изоляция.
</details>

<details><summary>Как структурировать аналитику, чтобы она оставалась поддерживаемой?</summary>

Трекинг-план как источник истины, соглашение об именах, типизированный клиент из плана, обёртка над провайдерами, декларативные точки трекинга, согласие пользователя, батчинг и `sendBeacon`, тесты и валидация, удаление неиспользуемых событий.
</details>

<details><summary>Почему чат поддержки ухудшает INP и что делать?</summary>

Виджет грузит сотни килобайт JS, регистрирует обработчики и выполняет долгие задачи на главном потоке при загрузке и взаимодействиях. Решение — фасад (загрузка по клику), отложенная загрузка, проверка влияния через LoAF.
</details>
