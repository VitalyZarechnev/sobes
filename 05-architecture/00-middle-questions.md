## Вопросы

<details><summary>Что такое SOLID? Приведите пример из фронтенда для каждого принципа.</summary>

S — компонент отображает, хук загружает данные; O — расширение через слоты и композицию; L — `IconButton` заменяет `Button`; I — узкие пропсы; D — зависимость от абстракции API-клиента, а не от `fetch`. Подробно — [принципы](01-principles.md).
</details>

<details><summary>Что такое DRY, KISS, YAGNI?</summary>

DRY — у знания один источник истины; KISS — простейшее работающее решение; YAGNI — не делать «на будущее». DRY вредит при случайном сходстве — абстракция обрастает флагами.
</details>

<details><summary>Что такое coupling и cohesion?</summary>

Coupling (связанность) — насколько модули зависят друг от друга; cohesion (связность) — насколько содержимое модуля относится к одной задаче. Цель — низкая связанность и высокая связность: изменения локальны.
</details>

<details><summary>Как вы структурируете фронтенд-проект?</summary>

По фичам и домену, а не по типам файлов; публичный API модулей; направление зависимостей сверху вниз; общий код без бизнес-логики отдельно. Методология — FSD (app → pages → widgets → features → entities → shared). Подробно — [FSD](03-fsd.md).
</details>

<details><summary>Что такое Feature-Sliced Design в двух словах?</summary>

Методология структуры: слои (app, pages, widgets, features, entities, shared), внутри — слайсы по доменам, внутри — сегменты (ui, model, api, lib). Модуль импортирует только из нижележащих слоёв и только через публичный API.
</details>

<details><summary>Чем MVC, MVP и MVVM отличаются?</summary>

Все отделяют модель от отображения. MVC — контроллер обрабатывает ввод и обновляет модель. MVP — презентер управляет пассивным представлением через интерфейс. MVVM — ViewModel с наблюдаемым состоянием и привязкой данных (Vue, Angular, MobX). Подробно — [MVC/MVP/MVVM](05-mvc-mvp-mvvm.md).
</details>

<details><summary>Что такое «умные» и «глупые» компоненты?</summary>

Контейнеры (данные, состояние, побочные эффекты) и презентационные компоненты (получают пропсы, отображают, сообщают о событиях). Упрощает тестирование и переиспользование. В эпоху хуков граница проходит между хуками/composables и компонентами отображения.
</details>

<details><summary>Что такое чистая архитектура на фронтенде?</summary>

Бизнес-правила (домен, use cases) не зависят от фреймворка, UI и инфраструктуры; зависимости направлены внутрь, внешние детали подключаются через интерфейсы (порты и адаптеры). Оправдана при сложной бизнес-логике. Подробно — [чистая архитектура](02-clean-architecture.md).
</details>

<details><summary>Что такое API и REST?</summary>

API — контракт взаимодействия программ. REST — стиль поверх HTTP: ресурсы с URL, методы со своей семантикой, коды ответов, stateless, HTTP-кэширование.
</details>

<details><summary>Какие паттерны проектирования вы применяли?</summary>

Наблюдатель (события, сторы), Стратегия (валидаторы), Адаптер (DTO → модель), Фасад (API-клиент), Компоновщик (дерево компонентов), Команда (undo/redo), Провайдер/DI (контекст, provide/inject). Лучше 2–3 с реальными примерами. Подробно — [паттерны](06-patterns-and-scaling.md).
</details>

<details><summary>Что такое монорепо?</summary>

Один репозиторий для нескольких приложений и пакетов с общими инструментами (pnpm workspaces, Turborepo/Nx): атомарные изменения и общий код, но нужна дисциплина границ и кэш задач.
</details>

<details><summary>Что такое микрофронтенды?</summary>

Разделение фронтенда на независимо разрабатываемые и деплоемые части разными командами (Module Federation, iframe, серверная композиция). Решают организационную проблему ценой сложности. Подробно — [микрофронтенды](08-microfrontends.md).
</details>
