## Теория

### Как выбрать

| | DOM / SVG | Canvas 2D | WebGL / WebGPU |
|---|---|---|---|
| Модель | retained: дерево узлов | immediate: пиксели | GPU-конвейер, шейдеры |
| Объектов комфортно | сотни – единицы тысяч | десятки тысяч простых | сотни тысяч – миллионы |
| События, CSS, a11y, текст | из коробки | вручную | вручную |
| Масштабирование | вектор, бесплатно | перерисовка | перерисовка |
| Сложность | низкая | средняя | высокая (библиотеки помогают) |
| Примеры | иконки, графики до ~1–5 тыс. элементов, диаграммы с интерактивом | графики с большим числом точек, рисовалки, 2D-игры, тепловые карты | карты (MapLibre), 3D, научная визуализация, миллионы точек |

Гибрид часто лучший: данные рисуются на canvas/WebGL, а оси, подписи, тултипы и элементы управления — в DOM поверх (доступно и чётко).

WebGPU — современный API GPU (compute-шейдеры, меньше накладных расходов); к 2025 году появился в Chrome, Safari и Firefox (в Firefox — сначала на Windows), проверяйте поддержку на целевых платформах. Three.js и Babylon.js умеют рендерить через него.

### Оптимизация Canvas 2D

1. **Меньше смен состояния**: группировать рисование по цвету и стилю (`fillStyle` меняется реже), один `beginPath` + много `rect` + один `fill`.
2. **Дешёвые примитивы**: `fillRect` быстрее `arc`; для тысяч одинаковых спрайтов — `drawImage` из заранее нарисованного офскрин-canvas.
3. **Слои**: статичный фон на отдельном canvas под динамическим — не перерисовывать каждый кадр.
4. **Грязные области**: перерисовывать только изменившиеся прямоугольники (`clearRect` + клип).
5. **Целые координаты** для `drawImage` (без субпиксельного сглаживания), `{ alpha: false }` у контекста, если фон непрозрачный.
6. **Без аллокаций в кадре**: пулы объектов, типизированные массивы — иначе паузы сборщика мусора дают рывки (см. [демо 03](demos/03-particles-loop.html)).
7. **Пространственный индекс** (сетка, quadtree) для hit-testing и коллизий вместо перебора всех пар — O(n) вместо O(n²).
8. **Не рисовать невидимое**: отсечение по вьюпорту.
9. **Ограничить DPR** на тяжёлых сценах (`Math.min(devicePixelRatio, 2)`).
10. **Не трогать DOM-раскладку в кадре**: чтение `getBoundingClientRect` после записи стилей вызывает принудительный reflow.

### OffscreenCanvas и воркеры

```js
// main.js: передаём управление холстом в воркер
const offscreen = document.querySelector('canvas').transferControlToOffscreen();
const worker = new Worker(new URL('./render-worker.js', import.meta.url), { type: 'module' });
worker.postMessage({ canvas: offscreen }, [offscreen]); // transfer, не копирование

// render-worker.js: рендер и физика не блокируют главный поток (ввод, скролл, React)
self.onmessage = ({ data }) => {
  const ctx = data.canvas.getContext('2d');
  const loop = () => {
    // ... рисуем
    requestAnimationFrame(loop); // доступен в воркере для OffscreenCanvas
  };
  loop();
};
```

Ввод (pointer events) по-прежнему приходит в главный поток — передавайте координаты сообщениями. Для больших данных — `SharedArrayBuffer` (нужна cross-origin isolation) или transferable `ArrayBuffer`.

### Профилирование

Performance-панель: длительность кадра (бюджет 16,7 мс на 60 Hz, 8,3 мс на 120 Hz), долгие задачи, GC-паузы. Rendering → Frame Rendering Stats (FPS, использование GPU). Для WebGL — расширение Spector.js (каждый draw call и состояние), `renderer.info` в Three.js.

### Доступность canvas

Canvas для скринридера — просто картинка. Варианты:
- `role="img"` + `aria-label` с кратким описанием; для графиков — **таблица данных** рядом (можно визуально скрытая) или текстовое резюме.
- Fallback-контент внутри `<canvas>…</canvas>`.
- Интерактивные элементы — параллельные DOM-элементы (кнопки, ползунки) с фокусом и клавиатурой; на canvas — только визуализация (см. клавиатуру в [демо 04](demos/04-drag-shapes.html)).
- Уважать `prefers-reduced-motion` — останавливать или упрощать анимацию.
- Не только цвет: формы маркеров, подписи.

## Вопросы с собеседований

<details><summary>SVG, Canvas или WebGL — как выбрать?</summary>

По количеству объектов, требованиям к интерактиву и доступности. SVG/DOM — до нескольких тысяч элементов, нужны события, CSS, доступность, чёткое масштабирование. Canvas 2D — десятки тысяч простых объектов, рисовалки, 2D-игры. WebGL/WebGPU — сотни тысяч и больше, 3D, эффекты на шейдерах. Часто — гибрид: данные на canvas, интерфейс и подписи в DOM.
</details>

<details><summary>График на 100 000 точек тормозит. Что делать?</summary>

Перейти с SVG на Canvas или WebGL; прореживание (downsampling, например LTTB) по разрешению экрана; батчинг отрисовки; рендер в воркере через OffscreenCanvas; пространственный индекс для тултипов; отрисовка только видимого диапазона; тяжёлые вычисления заранее.
</details>

<details><summary>Как сделать canvas-визуализацию доступной?</summary>

Текстовое описание (`role="img"`, `aria-label`), таблица данных или резюме для скринридеров, интерактив через реальные DOM-элементы с клавиатурой, `prefers-reduced-motion`, не только цвет.
</details>

<details><summary>Зачем OffscreenCanvas?</summary>

Перенести рендер (и физику) в воркер, чтобы анимация не тормозила из-за работы главного потока (фреймворк, обработчики), и наоборот — тяжёлый рендер не ухудшал отзывчивость интерфейса (INP).
</details>
