## Теория

### Зачем фронтендеру WebGL

Чаще всего вы будете работать через библиотеки (Three.js, Babylon.js, PixiJS, MapLibre, deck.gl), но без понимания конвейера невозможно объяснить, почему сцена тормозит, почему «мерцают» полигоны или как написать эффект на шейдере.

### Конвейер

```text
JS: данные вершин в буферах (Float32Array)
  ↓ gl.bufferData — загрузка в память GPU
Вершинный шейдер: для каждой вершины вычисляет позицию gl_Position (clip space -1..1)
  ↓
Сборка примитивов и растеризация: треугольники → фрагменты (кандидаты в пиксели)
  ↓ varying-значения интерполируются по треугольнику
Фрагментный шейдер: для каждого фрагмента вычисляет цвет
  ↓ тест глубины, смешивание (blending)
Кадр (framebuffer) → экран
```

Шейдеры пишутся на GLSL и выполняются **параллельно** на тысячах ядер GPU — поэтому нет доступа к соседним вершинам и пикселям и нет общего изменяемого состояния.

### Входные данные шейдеров

| | Где задаётся | Меняется | Пример |
|---|---|---|---|
| attribute (`in` в вершинном) | буфер | на каждую вершину | позиция, нормаль, UV, цвет |
| uniform | `gl.uniform*` | на draw call | матрицы, время, цвет материала, текстура |
| varying (`out` → `in`) | вершинный шейдер | интерполируется по фрагментам | цвет, нормаль, UV для фрагментного |

### Матрицы

- **Model** — из локальных координат объекта в мировые (положение, поворот, масштаб).
- **View** — из мировых в координаты камеры (обратная к матрице камеры).
- **Projection** — перспектива или ортографика: из пространства камеры в clip space.

`gl_Position = projection * view * model * vec4(position, 1.0)`. Порядок умножения матриц важен (как порядок трансформаций в [Canvas 2D](01-canvas-2d-basics.md)). Матрицы 4×4 — однородные координаты, чтобы перенос тоже был умножением.

### Текстуры

Изображение загружается в GPU (`texImage2D`), в шейдере читается по UV-координатам (`texture(uSampler, vUv)`). Параметры: фильтрация (`LINEAR`, `NEAREST`), mipmaps для уменьшенных текстур, повторение. Сжатые форматы (KTX2/Basis) экономят видеопамять и время загрузки.

### Draw calls и производительность

Draw call — команда «нарисуй» (`drawArrays`/`drawElements`) с текущим состоянием (программа, буферы, текстуры, uniform). Каждый вызов имеет накладные расходы на CPU-стороне, смены состояния дорогие. Поэтому:
- **инстансинг** (`drawArraysInstanced`, `InstancedMesh` в Three.js) — тысячи одинаковых объектов одним вызовом (см. [демо 06](demos/06-threejs-scene.html));
- **батчинг** — склеивание геометрии статичных объектов;
- **атласы текстур** — меньше переключений текстур;
- сортировка по материалу, отсечение невидимого (frustum culling), уровни детализации (LOD).

Узкие места GPU — fill rate (сложный фрагментный шейдер × много пикселей × высокий DPR) и overdraw (много прозрачных слоёв).

### Частые проблемы

- **Z-fighting** (мерцание совпадающих плоскостей) — разнести, увеличить `near` камеры.
- **Потеря контекста** (`webglcontextlost`) — на мобильных при нехватке памяти: обрабатывать восстановление ресурсов.
- **Утечки видеопамяти** — освобождать `deleteBuffer`/`deleteTexture` (в Three.js — `dispose()` у геометрий, материалов, текстур).
- **Неверный размер буфера** — синхронизировать `canvas.width/height` и `gl.viewport` с CSS-размером × DPR.

### WebGPU

Новый API: явные пайплайны и bind groups, WGSL вместо GLSL, compute-шейдеры для вычислений общего назначения (частицы, физика, ML), меньше накладных расходов на CPU. Для фронтенда чаще всего — через Three.js (`WebGPURenderer`) или Babylon.js.

## Вопросы с собеседований

<details><summary>Что делают вершинный и фрагментный шейдеры?</summary>

Вершинный шейдер для каждой вершины вычисляет её положение в clip space (обычно умножая на матрицы) и передаёт данные для интерполяции. Фрагментный — для каждого фрагмента растеризованного треугольника вычисляет цвет (освещение, текстуры, эффекты).
</details>

<details><summary>Чем uniform отличается от attribute?</summary>

Attribute — данные каждой вершины из буфера (позиция, нормаль), uniform — одно значение на весь draw call (матрицы, время, цвет материала).
</details>

<details><summary>Что такое draw call и как сократить их число?</summary>

Команда отрисовки с текущим состоянием GPU. Каждая несёт накладные расходы CPU и смены состояния. Сокращают инстансингом, батчингом статичной геометрии, атласами текстур, сортировкой по материалам, отсечением невидимого.
</details>

<details><summary>Зачем нужны матрицы model, view, projection?</summary>

Model переводит объект в мировые координаты, view — в координаты камеры, projection — в clip space с перспективой. Разделение позволяет переиспользовать камеру для всех объектов и объект — для разных камер.
</details>
